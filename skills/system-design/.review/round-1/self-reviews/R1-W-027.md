## Checklist

This file is a standalone bash lint script (CR-X5 enforcer). Applicable CRs:
CR-X5 (feature-module-traceability, the check this script implements),
plus general script-quality checks: pure-bash requirement, set -euo pipefail,
correct exit codes, correct output path, CLI flag support, and PRD path
resolution consistency with X3/X4.

- **Pure bash (`#!/usr/bin/env bash`)**: PASS — shebang is `#!/usr/bin/env bash`;
  no python3 or other interpreter invocations. All logic uses bash builtins,
  `grep`, `sed`, `awk`, `sort`, `tr`, `printf`, `find`. `awk` is used for
  column-index extraction from pipe-delimited table rows (BSD/GNU compatible).

- **`set -euo pipefail` present**: PASS — line 3 of the script (after the
  comment header block).

- **Exit codes correct**: PASS — exit 0 (no findings or PRD unresolvable and
  checks pass), exit 1 (findings present AND (blocker found OR --strict set)),
  exit 2 (usage/env error). Verified by smoke tests 1–8: no-args → 2,
  nonexistent-dir → 2, blocker finding → 1, mechanical only without --strict → 0,
  mechanical with --strict → 1, clean design → 0.

- **Check 1 (blocker): orphaned PRD feature**: PASS — script lists
  `${PRD_FEATURES_DIR}/F-*.md`, extracts F-NNN from each filename, then checks
  the cell-map for any non-empty symbol in the feature's row. A feature with
  zero ✦/△ cells emits a blocker LINT-NNN.md. Verified: F-003 with no matrix
  row triggers blocker + exit 1 (smoke test 3).

- **Check 2 (mechanical): Source Features ↔ matrix ✦ bidirectional sync**: PASS —
  two sub-checks: (a) F-NNN in module's Source Features must have ✦ in matrix
  at (F-NNN, M-NNN); (b) F-NNN with ✦ in matrix must appear in module's Source
  Features. Both directions are verified. Mismatched △ vs ✦ is also detected
  and the reasoning message distinguishes the three cases (blank, △, unexpected
  symbol). Verified: smoke test 4 emits LINT-001 (F-001 in Source Features but
  blank matrix) and LINT-002 (F-002 in matrix ✦ but absent from Source Features).

- **PRD path resolution**: PASS — reads the `**Source:**` line from README.md,
  extracts the first markdown link's path (parentheses), resolves relative to
  DESIGN_DIR, strips trailing `README.md`, and confirms the resolved path is a
  directory. If resolution fails or features/ subdir is absent, emits WARNING to
  stderr and skips Check 1 (not an error). This matches the "skip with warning if
  PRD path unresolvable" requirement. Verified: smoke test 7 (no Source line →
  warning + OK 0 findings), smoke test 3 (relative `../prd-test/README.md` →
  correctly resolved).

- **Output path `<design-dir>/.reviews/LINT-<NNN>.md`**: PASS — `.reviews/`
  directory is created with `mkdir -p`; sequence numbers zero-padded to 3 digits
  via `printf '%03d'`; numbering continues from highest existing LINT-NNN.md so
  repeated runs append rather than overwrite.

- **LINT file structure (severity / CR-id / file / anchor / title / reasoning / fix)**:
  PASS — each LINT-NNN.md contains: heading with sequence, CR-id (CR-X5),
  severity (blocker for orphaned features, mechanical for Source Features
  mismatches), relative file path, anchor (section heading), title, reasoning
  paragraph quoting the CR-X5 rule, and a concrete suggested fix with options A/B/C
  where applicable.

- **CLI flags `--quiet` and `--strict`**: PASS — `--quiet` suppresses per-issue
  stdout lines (only final summary line emitted); `--strict` forces exit 1 even
  when all findings are mechanical. Both tested in smoke test 5.

- **Symbol extraction (✦ / △)**: PASS — uses `grep -q '✦'` and `grep -q '△'`
  on cell text; these are the exact Unicode characters used in the
  Feature-Module Mapping matrix template. Blank cells produce empty symbol.

- **Matrix header parsing**: PASS — header row is identified as the first
  table row containing an M-NNN token; column indices are extracted via `awk`
  with `FS="|"` splitting. Each data row is parsed at the same column index,
  giving the correct cell for each (F-NNN, M-NNN) pair. Separator rows
  (containing only `[-: |]`) are excluded from data rows.

- **Module file lookup (slug suffix)**: PASS — for each M-NNN, the script
  tries `M-NNN-*.md` glob and `M-NNN.md` fallback. If no file exists, Check 2

  class, not X5). Verified in smoke test 8.

- **Source Features dual-location parsing**: PASS — script collects F-NNN tokens
  from both the header callout line (`> **Source Features:** F-001, F-003`) and
  the `## Source Features` section body (markdown link form `[F-NNN: ...](...)`).
  Both forms are used in actual module files per the module template.

- **Temp file cleanup**: PASS — three temp files (TMP_COL_MAP, TMP_DATA_ROWS,
  TMP_CELL_MAP) are created in `/tmp/` and removed unconditionally at the end
  via `rm -f`.

- **BSD/macOS compatibility**: PASS — `awk`, `grep -E`, `grep -oE`, `sed`,
  `sort -u`, `tr`, `printf`, `wc -l` all available on macOS default shell
  environment. No GNU-only flags used. `grep -q '✦'` works with UTF-8 on macOS.

- **Smoke tests (functional)**: PASS — 8 scenarios exercised:
