## Checklist

This file is a cross-file structural lint script (CR-X2 enforcer). Applicable criteria:

plus general script-quality checks: pure-bash requirement, `set -euo pipefail`,

- **Pure bash (`#!/usr/bin/env bash`)**: PASS — shebang is `#!/usr/bin/env bash`.
  All logic uses bash builtins, `find`, `sed`, `tr`, `printf`. No Python, awk
  pipelines, or third-party tools. Confirmed with a grep for `python` / `ruby` /
  `node` — none present.

- **`set -euo pipefail` present**: PASS — on line 42 (after the comment header block).

- **Skip when api/ absent**: PASS — the script checks `if [ ! -d "$API_DIR" ]` after
  resolving the design dir; if absent it emits an INFO message and exits 0. Verified
  by smoke test 3 (temp dir with no api/ subdirectory → `INFO: no api/ directory …
  CR-X2 skipped.` → exit 0).

- **Set A extraction (modules API Surface col 1)**: PASS — for each `M-*.md` file,
  the parser enters `## API Surface` on an H2 heading, skips the header row and
  separator rows, then reads column 1 (pipe-delimited) from every data row. Method
  token is matched case-insensitively (uppercase and lowercase patterns); both are
  normalised to uppercase before storage. Verified by smoke test 12 (lowercase `get`
  in module cell matched `## GET /v1/tasks` in api/).

- **Set B extraction (api/ endpoint headings)**: PASS — the script matches two
  heading patterns:
  (1) Direct: `^##[[:space:]]+(METHOD)[[:space:]]+(/...)` — handles the standard
      case `## GET /v1/tasks`.
  (2) Decorated: `^##[[:space:]].*[[:space:]](METHOD)[[:space:]]+(/...)` — handles
      `## [Deprecated] GET /v1/tasks` and similar prefixes.
  Pattern 1 is tried first; Pattern 2 only if Pattern 1 fails. Only H2 headings
  (`##`) are matched; `###` or deeper are not picked up. Verified by smoke test 8
  (`## [Deprecated] GET /v1/tasks` was matched and correctly paired with the
  module's `GET /v1/tasks` cell → 0 violations).

- **Root cause fix — regex for direct headings**: PASS — the initial draft used a
  single pattern `^##[[:space:]].*[[:space:]](METHOD)` which requires at least one
  character before the first space (failing `## GET /v1/tasks` where the method
  follows `## ` directly). Fixed by splitting into two patterns: (1) direct
  (no prefix) and (2) decorated (prefix present). Verified by smoke tests 4–14.

- **Trailing-slash normalisation**: PASS — after extracting both the method and path,
  the path has its trailing slash stripped if `${#path} > 1` (the bare `/` is kept
  intact). Verified by smoke test 13: `## GET /v1/tasks/` in api/ matches
  `GET /v1/tasks` in the module cell → 0 violations.

- **Bidirectional findings (A−B and B−A)**: PASS — the script iterates `a_keys` and
  checks membership in `B_ENDPOINT` (A−B: module-missing), then iterates `b_keys`
  and checks membership in `A_ENDPOINT` (B−A: api-orphan). Verified by smoke tests
  5 (A−B only), 6 (B−A only), and 14 (both directions simultaneously, 3 LINT files
  written with sequential numbering 001–003).

- **Empty associative array handling under `set -u` (bash 5.3 compat)**: PASS — bash
  5.3 on macOS arm64 raises "unbound variable" for `${#assoc[@]}` and `${!assoc[@]}`
  when the associative array is empty under `set -u`. Fixed with `set +u` / `set -u`
  guards around all associative array expansions (`${#...}`, `${!...[@]}`, `${...[key]+set}`).
  Verified by smoke tests 9 and 10 where one set is empty.

- **Issue file format (severity / CR-id / file / line / endpoint / fix)**: PASS —
  each `LINT-NNN.md` contains: H1 heading with sequence number and CR-X2 label,
  `**Severity**: blocker`, `**CR-id**: CR-X2`, relative `**File**`, `**Line**`,
  `**Endpoint**`, a `## Finding` section with a human-readable sentence, and a
  `## Suggested Fix` section with a concrete action (either "add heading to api/ or
  fix the literal" for module-missing, or "add to module's API Surface or remove the
  endpoint" for api-orphan). Verified by smoke test 5 (full LINT-001.md content
  printed and confirmed).

- **Output path `<design-dir>/.reviews/LINT-<NNN>.md`**: PASS — `.reviews/` is
  created with `mkdir -p` after the api/ check. Sequence numbers are zero-padded to
  three digits via `printf "%03d"`; numbering continues from the highest existing
  `LINT-NNN.md` (so repeated runs append rather than overwrite). Confirmed by
  smoke test 14: three sequential LINT files 001–002–003 written.

- **Exit codes correct (0/1/2)**: PASS —
  - exit 2: missing `<design-dir>`, extra positional arg, unknown flag, dir not found.
  - exit 0: api/ absent (skip), no violations found.
  - exit 1: one or more violations found.
  Verified by smoke tests 1 (exit 2), 2 (exit 2), 3 (exit 0), 4 (exit 0), 5–6 (exit 1).

- **`--quiet` flag**: PASS — when set, no per-violation lines and no summary line
  are printed to stdout; LINT files are still written and exit code is unaffected.

- **`--strict` flag**: PASS — per the spec it is reserved for pipeline use; in this

- **No modules/ dir graceful handling**: PASS — the modules scan is guarded with

- **Limitation documentation in comment header**: PASS — five limitations are
