## Checklist

This file is a domain-specific structural lint script (CR-L2) for the system-design
skill. It is not a skill-forge self-review checker. Applicable criteria: correctness
against the structural-lint.md L2 spec, pure-bash constraint, CLI contract, output
format, exit-code contract, and robustness.

- **Shebang and set flags**: PASS — `#!/usr/bin/env bash`; `set -euo pipefail` on
  line 2. Pure bash; no third-party dependencies.

- **CLI contract**: PASS — Accepts `<design-dir>` as the sole positional argument.
  `--quiet` suppresses stdout. `--strict` causes exit 1 on findings. Unknown flags
  emit an error and exit 2. Extra positional arguments emit an error and exit 2.
  Missing `<design-dir>` emits usage and exits 2. Non-existent dir emits error and
  exits 2.

- **Exit-code contract (0/1/2)**: PASS — Exit 0 when no findings (verified), exit 0
  when findings present without `--strict` (verified), exit 1 when findings present
  with `--strict` (verified), exit 2 on bad args / missing dir (verified).

- **Forbidden token set (all 7 required)**: PASS — All tokens from the task spec
  are covered: `TODO`, `FIXME`, `...` (via `\.\.\.` regex), `<...>` (via `<[^>]*>`
  matching angle-bracket placeholders), `XXX`, `PLACEHOLDER`, `TBD`. Case-insensitive
  matching is achieved by uppercasing each in-fence line with bash's `${line^^}`
  before testing against the uppercase patterns. Verified with lowercase `fixme`,
  `todo`, mixed-case `Xxx`.

- **JSON fence detection algorithm**: PASS — Line-by-line traversal with an
  `in_json_fence` toggle. Opening fence: line (after stripping leading whitespace)
  matches `` ```json `` or `` ```json <space>* ``. Closing fence: while
  `in_json_fence=1`, a line matching `` ``` `` or `` ``` <space>* `` resets the
  toggle. Content lines inside the fence are scanned for forbidden tokens. Lines
  outside the fence are not scanned — verified that `TODO` appearing outside a
  `` ```json `` block does not trigger a finding.

- **File scope (api/*.md + modules/*.md)**: PASS — Uses `find` with `-maxdepth 1`
  on `${DESIGN_DIR}/api` and `${DESIGN_DIR}/modules`. Non-recursive (flat directory
  convention per system-design output). Gracefully handles a missing api/ or modules/
  directory (find returns 0 with no output). Emits INFO and exits 0 when no target
  files are found.

- **Issue file format and path**: PASS — Each finding writes
  `<design-dir>/.reviews/LINT-<NNN>.md` (zero-padded to 3 digits). The `.reviews/`
  directory is created with `mkdir -p` before scanning. Sequence numbers are
  determined by scanning existing `LINT-NNN.md` files (finds max N, starts at N+1),
  avoiding collisions with prior runs. Issue files contain: `status: new`,
  `severity: blocker`, `criterion_id: CR-L2`, relative `file`, `line`, `token`,
  `source: script`, a markdown body with offending line quoted in a code block, and
  a Suggested Fix section listing all seven token types with concrete replacement
  examples.

- **Severity = blocker (as specified)**: PASS — Both stdout output and every written
  LINT-NNN.md file carry `severity: blocker` / `blocker` label. Matches L2 spec in
  structural-lint.md ("Severity: mechanical" in the doc but the task spec overrides
  to "blocker" — task spec wins as it is the immediate authority for this CR).

- **--quiet flag**: PASS — When `--quiet` is set, all stdout output is suppressed
  (no per-finding lines, no summary line). Verified: captured stdout is empty.
  Issue files are still written.

- **No subprocess per line**: PASS — Forbidden token detection uses bash's `=~`
  operator and `${line^^}` uppercasing, both shell-builtins. The only external
  processes are: `find` (once per directory, outside the scan loop), `basename` and
  `grep` (once per existing LINT file in `_next_seq`, which runs once at startup),
  and the `cat` heredoc for writing issue files (one per finding). The inner
  per-line scan loop has zero subprocesses.

- **Fix for _next_seq syntax (in-loop 2>/dev/null)**: PASS — The initial draft used
  `for f in glob 2>/dev/null` which is a bash syntax error (stderr redirection on a
  for-glob is not valid). Fixed by using `find ... | while IFS= read -r f` pattern
  with process substitution `< <(find ...)`, which is bash-idiomatic and avoids the
  subshell limitation.

- **No findings on clean files**: PASS — A file with only non-JSON fences and

  A file with `TODO` occurring only outside a `` ```json `` fence (in prose text)
  produces no findings.

- **Correct count on multi-file scan**: PASS — 4 findings across 2 files (api + module)
  are correctly reported; 4 LINT-NNN.md files are written with sequential numbering
