This file is a standalone bash lint script (CR-X3 enforcer). Applicable CRs:

- **Pure bash (`#!/usr/bin/env bash`)**: PASS — shebang is `#!/usr/bin/env bash`.
  All logic uses bash builtins, `grep`, `sed`, `awk`, `find`, `sort`, `tr`, `cd`.
  No Python/Ruby/Node inline heredocs.

- **`set -euo pipefail` present**: PASS — second non-comment line of the script.

- **Exit codes correct**: PASS — exit 0 (no violations or PRD/architecture
  skipped), exit 1 (at least one blocker; or at least one finding + --strict),
  exit 2 (usage/env error). Verified by smoke tests: no-args → 2, nonexistent
  dir → 2, PRD not resolvable → 0, all covered → 0, missing file → 1,
  --strict + clean → 0.

- **PRD path resolution — three patterns**: PASS
  - Pattern a: `grep -i 'Source:'` + `sed -n 's/.*(\([^)]*\)).*/\1/p'` extracts
    the href from lines like `**Source:** [name](../path/)`. Tested successfully
    against a real README.
  - Pattern b: `grep -iE '^\s*[-*]\s*\[prd'` + same sed extraction covers
    References section links like `- [PRD](../prd-refs/README.md)`.
  - Pattern c: broad fallback — scans all non-http markdown link hrefs in the
    file; catches custom formats that don't match patterns a or b.
  - All candidates normalize trailing slash, strip fragment anchors, strip
    `.md` filename to get parent dir; resolved via `cd "$design_dir" && cd
    "$candidate" && pwd` in a subshell with `|| true` to suppress errors under
    `set -e`.

- **BSD/macOS grep compatibility — critical fix**: PASS — initial implementation
  used `grep -oE '[^\n]*'` patterns which macOS BSD grep misparsed when input
  contained literal `[` characters (the match was truncated). Replaced with
  `sed -n 's/.*(\([^)]*\)).*/\1/p'` for href extraction throughout, which is
  portable across BSD and GNU sed. Also verified that `grep -oE '\([^)]*\)'`
  (used in the prd/ fallback) silently fails on macOS when the input contains
  `[` before `(`. All extraction now goes through sed. One smoke test confirmed
  the failure before the fix, and all tests pass after.

- **Output path `<design-dir>/.reviews/LINT-<NNN>.md`**: PASS — `.reviews/`
  created with `mkdir -p`; sequence zero-padded to three digits via
  `printf '%03d'`; numbering continues from the highest existing LINT-NNN.md
  (repeated runs append LINT-002, LINT-003, etc.).

- **Issue file structure (severity / CR-id / file / title / reasoning / fix)**:
  PASS — Each LINT-NNN.md contains: heading with sequence, severity (blocker),
  CR-id (CR-X3), file (README.md), title, reasoning (explains why silent
  omission is a problem), and a two-option suggested fix (add a PRD Policy cell
  reference OR add an N/A row naming the file).

- **Detection logic — covered vs. uncovered**: PASS
  - An architecture file is considered covered if its basename (with or without
    .md extension) appears anywhere in the `## Implementation Conventions`
    section text. This handles: bare filename in a cell, relative path
    containing the filename, N/A rows naming the file.
  - The conventions section is extracted via a state-machine reader (enters on
    `## Implementation Conventions`, exits on next `##` heading).
  - `basename_covered()` tests both `bname` (e.g. `logging.md`) and `bname_noext`
    (e.g. `logging`) using `grep -qF` (fixed-string, not regex) to avoid
    special-character interpretation.

- **Skip conditions**: PASS

    exit 0.
  - PRD resolves but `architecture/` absent → `OK 0 findings — PRD architecture/
    directory not found, skipped`; exit 0.
  - `architecture/` contains no `.md` files → `OK 0 findings — architecture/
    contains no .md files`; exit 0.

- **CLI flags `--quiet` and `--strict`**: PASS
