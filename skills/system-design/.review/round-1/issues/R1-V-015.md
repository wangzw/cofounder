# CR-L11

writer-subagent's "Mandatory cross-skill carryovers" section instructs the writer to inject SKILL.md cost-control sections + register `skill-md-cost-control-sections` CR — but system-design's writer never produces a SKILL.md or review-criteria.md (those belong to the SKILL itself, not the design artifact)

## Reasoning

`generate/writer-subagent.md` Mandatory cross-skill carryovers (writer-of-meta-files only):
> "Two artifacts in the standard FromScratch `add:` set carry MANDATORY content that must propagate across every generated skill regardless of artifact domain. Writers of these specific paths MUST include the carryover content verbatim from the template:
> - `SKILL.md` — MUST include `## Model Tiers` + `### Per-dispatch model override` ...
> - `common/review-criteria.md` — MUST register the meta-CR `skill-md-cost-control-sections` ..."

This instruction makes sense for the SKILL-FORGE skill (which generates new skills, where SKILL.md and common/review-criteria.md are the produced artifacts). But for **system-design**, the produced artifacts are:

- `docs/raw/design/YYYY-MM-DD-{slug}/README.md` (design overview)
- `docs/raw/design/YYYY-MM-DD-{slug}/modules/M-NNN-{slug}.md` (module specs)
- `docs/raw/design/YYYY-MM-DD-{slug}/api/API-NNN-{slug}.md` (API contracts)

`SKILL.md` and `common/review-criteria.md` are part of the SKILL itself — they were already generated by skill-forge when system-design was bootstrapped, and writers in system-design never re-author them as part of their dispatch. The plan.add list (per `from-scratch.md` Step 5 / `planner-subagent.md` Output Contract) explicitly covers only `README.md`, `modules/M-NNN-*.md`, `api/API-NNN-*.md` — never `SKILL.md` or `common/review-criteria.md`.

The cross-skill-carryover paragraph is leftover skill-forge-specific guidance that is meaningful for skill-forge writers but a no-op (and confusing) for system-design writers. It's a CR-L11 issue: writer-subagent declares a contract about SKILL.md content that never applies in this skill, suggesting copy-paste carryover from a sibling skill-forge variant without domain re-targeting.

The risk: a system-design writer reading the section may (a) waste tokens trying to determine if their dispatched leaf qualifies as "writer-of-meta-files", or worse (b) fabricate a SKILL.md or common/review-criteria.md inside the design output directory, polluting the design artifact.

## Suggested Fix

Either:

(a) Delete the "Mandatory cross-skill carryovers" section entirely from `generate/writer-subagent.md`. system-design's writers never produce skill-level meta-files. The CR-S15 `skill-md-cost-control-sections` registration is required for skill-forge's writer, not for system-design's writer.

(b) Reframe the section as system-design-specific carryovers — e.g., "Module specs MUST inline data models; README MUST contain Feature-Module mapping matrix" — pointing at the actual mandatory content for THIS skill's artifact domain. This converts a stale skill-forge instruction into useful system-design enforcement.

Option (b) preserves the slot for cross-skill discipline but re-targets it to the system-design domain. Option (a) is simpler if domain-specific carryovers are already covered by the per-leaf-type tables earlier in writer-subagent.md.
