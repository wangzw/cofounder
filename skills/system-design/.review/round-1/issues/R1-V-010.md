# CR-L11

writer-subagent's Self-Review section references `generate/in-generate-review.md` for the CR applicability table, but no such file exists in the skill inventory

## Reasoning

`generate/writer-subagent.md` Output Contract — Write 2 (Self-Review Archive) instructs:
> "Content structure: ... See `generate/in-generate-review.md` for CR applicability table."

And the Self-Review Discipline section repeats:
> "Apply only the CRs relevant to this file type (see `generate/in-generate-review.md` table)."

`SKILL.md` Configuration & Subagent Files section enumerates every file under `generate/`:
- `generate/domain-consultant-subagent.md`
- `generate/planner-subagent.md`
- `generate/writer-subagent.md`
- `generate/from-scratch.md`
- `generate/new-version.md`

There is no `generate/in-generate-review.md` listed and none exists on disk under `skills/system-design/generate/`. A writer following the prompt will look for the file, fail to find it, and either (a) produce a self-review with no CR applicability filter (oversharing FAIL rows on CRs that don't apply to its file type) or (b) skip self-review entirely (silent CR-L09 violation — blocker_scope FAIL rows are how cross-reviewer learns about scope-external conflicts).

The writer-subagent in turn defines the FULL_PASS/PARTIAL semantics that the orchestrator depends on (`completed` event schema requires `self_review_status` and `fail_count` for writer). If the in-generate-review table is missing, the writer either fakes the filter or skips it; either way the self-review archive becomes unreliable input to the cross-reviewer's "Writer Self-Review FAIL-Row Handling" loop.

## Suggested Fix

Either:

(a) Create `generate/in-generate-review.md` that maps file-type (module spec / API contract / README) → applicable CRs (CR-L01..CR-L11 + CR-D01..CR-D10 + CR-S* domain script CRs). The table can be a single grid: rows = CR-IDs, columns = file types, cells = "applies / N/A".

(b) Inline the applicability table directly into `generate/writer-subagent.md` (the Self-Review Discipline section is the natural home), and remove the file reference. This is the more self-contained option (matches the skill's CR-D06 self-contained-files principle).

Option (b) is preferable since the writer is dispatched once per file and the table is small enough to fit inline.
