# CR-L11

module-template's Boundary Enforcement table columns contradict CR-L3 / domain-glossary `Boundary Enforcement` definition

## Reasoning

`common/review-criteria.md` CR-L3 (boundary-enforcement-cols):
> "Constraint, Tool/Lint/Test (a named rule identifier — not descriptive English like 'custom lint' or 'structural check'), File Path (resolves to an actual file in the repo root), CI Job (matches a job in the Development Infrastructure module's CI pipeline definition)."

`common/domain-glossary.md` `Boundary Enforcement` term:
> "Required columns (four): `Constraint`, `Tool / Lint / Test`, `File Path`, `CI Job`."

`SKILL.md` Core Principles section also calls out "Boundary Enforcement 4-cols" as a legacy invariant to preserve.

`common/templates/module-template.md` Boundary Enforcement section (line ~236):
> "| Operation | Authorization | Validation | Error response |"

Like R1-V-002, the template preserves the lint-checked column count (4) but uses entirely different names and semantics. `Operation` is not `Constraint`; `Authorization` and `Validation` are not `Tool/Lint/Test`; `File Path` and `CI Job` are missing. The column-definition comment in the template documents the wrong set ("Operation — one concrete rule in descriptive English; 'code should be clean' is rejected") instead of the CR-L3 contract.

`scripts/check-boundary-enforcement-cols.sh` (referenced by CR-L3) will look for the canonical headers and reject every row that template-following writers produce, every time. Because lint runs BEFORE LLM review (the two-phase quality gate), every module spec will fail the gate at Step 9 of from-scratch.md.

## Suggested Fix

Replace the Boundary Enforcement table header and column-definition comments in `module-template.md` with the canonical four columns: `Constraint | Tool / Lint / Test | File Path | CI Job`. Move the per-row content (auth middleware, zod schema, HTTP error responses) into the API Surface table where it logically belongs (Auth column + Error Codes column), or into the Error Handling section.
