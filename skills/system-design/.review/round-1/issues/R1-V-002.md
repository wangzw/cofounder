# CR-L11

module-template's API Surface table columns contradict CR-L4 / domain-glossary `API surface` definition

## Reasoning

Three documents must agree on the API Surface table column set, because `scripts/check-api-surface-cols.sh` (declared by CR-L4 in `common/review-criteria.md`) enforces the column shape mechanically.

`common/review-criteria.md` CR-L4 (api-surface-cols):
> "Method+Path | Auth & Role | Success | Error Codes (at least one status code with error-type string) | Request Example (anchor link) | Response Example (anchor link) | Constraints"

`common/domain-glossary.md` `API surface` term:
> "Required columns (seven): `Method + Path`, `Auth & Role`, `Success`, `Error Codes`, `Request Example`, `Response Example`, `Constraints`."

`common/templates/module-template.md` API Surface section (line ~199):
> "| Method | Path | Auth | Roles | Rate | Idempotency | Owner |"

The template ships seven columns, matching the lint count, but the column NAMES and SEMANTICS are completely different: `Method+Path` is split into two; `Auth & Role` is split into `Auth | Roles`; `Success` and `Error Codes` are missing entirely; `Request Example` and `Response Example` are replaced by a single `Owner` link; `Constraints` is absent; `Rate` and `Idempotency` are not in the canonical set. A writer following this template will produce module files that fail CR-L4 lint on every row — and the SKILL.md "Core Principles #7" specifically calls out "API Surface 7-cols" as a legacy invariant to preserve.

The same template's column-definition comment block reinforces the divergence: it documents "Method", "Path", "Auth", "Roles", "Rate", "Idempotency", "Owner" — none of which are the lint-checked columns.

## Suggested Fix

Replace the API Surface table header and column-definition comments in `module-template.md` with the canonical seven columns: `Method+Path | Auth & Role | Success | Error Codes | Request Example | Response Example | Constraints`. Move `Rate` and `Idempotency` into the per-endpoint subsections of the API contract file (where they belong in `api-template.md`'s "Rate Limits" and "Auth" subsections), not into the module's API Surface table.
