# CR-L11

cross-reviewer and adversarial-reviewer use different issue frontmatter schemas (id vs issue_id) and severity vocabularies (critical/error/warning/info vs blocker/important/suggestion)

## Reasoning

Both reviewers write to the same directory (`.review/round-<N>/issues/` in-pipeline; `.reviews/` in `--review` mode) and both produce REVIEW-NNN.md files. The summarizer and judge consume them in aggregate, so their frontmatter schemas MUST be the same.

`review/cross-reviewer-subagent.md` Output Contract:
```yaml
---
id: R<N>-<seq>
round: <N>
file: <target-relative-path>
criterion_id: CR-D04
severity: critical | error | warning | info
source: cross-reviewer | self-review-escalation
reviewer_variant: cross
status: new | persistent | resolved | regressed
---
```

`review/adversarial-reviewer-subagent.md` Output Contract:
```yaml
---
issue_id: <target-slug>-round-<N>-<seq>
round: <N>
file: <target-relative-path>
criterion_id: <CR-ID>
severity: blocker | important | suggestion
source: adversarial-reviewer
reviewer_variant: adversarial
status: new | persistent | resolved | regressed
---
```

Three concrete divergences:

1. The primary key is `id:` in cross-reviewer, `issue_id:` in adversarial-reviewer. Any script or downstream prompt that greps `^id:` will skip every adversarial issue (and vice versa).
2. The ID format is `R<N>-<seq>` for cross-reviewer (matching the trace_id convention `R<round>-<role>-<seq>` reduced to R<round>-<seq> for issues), but `<target-slug>-round-<N>-<seq>` for adversarial — utterly different shape. The cross-reviewer body example R1-042 won't sort consistently with adversarial myapp-design-round-1-007.
3. The severity vocabulary is `critical|error|warning|info` (matching review-criteria.md's stated severity-to-priority mapping) for cross-reviewer, but `blocker|important|suggestion` for adversarial. The judge cannot apply a uniform priority threshold; the summarizer cannot cluster by severity.

`review-criteria.md` line 9 establishes the severity-to-priority mapping as `critical = 1, error = 2, warning = 3` — this is the canonical vocabulary. Adversarial-reviewer's `blocker|important|suggestion` does not appear anywhere in `review-criteria.md`.

## Suggested Fix

Adopt cross-reviewer's frontmatter schema as canonical (matches review-criteria.md severity vocabulary):
- Use `id:` (not `issue_id:`).
- Use `R<N>-<seq>` ID format (zero-padded 3 digits).
- Use severity values `critical | error | warning | info`.

Update `adversarial-reviewer-subagent.md` Output Contract block and the body example block accordingly. Keep `source: adversarial-reviewer` and `reviewer_variant: adversarial` to distinguish origin.
