# CR-L11

adversarial-reviewer requires `state.yml adversarial_review_triggered: true` flag to fire, but from-scratch.md Step 10 dispatches it unconditionally and review/index.md dispatches it on every --review run — neither sets the flag

## Reasoning

`review/adversarial-reviewer-subagent.md` Trigger Condition:
> "Dispatched by orchestrator ONLY when `config.yml adversarial_review.triggered_by` threshold is met (default: any in-generate critical or error issue). MUST check `state.yml` for the `adversarial_review_triggered: true` flag before beginning — if absent, emit a no-op ACK and return immediately (do not file false issues)."

`generate/from-scratch.md` Step 10 (Cross-Reviewer + Adversarial-Reviewer):
> "Both reviewers are dispatched simultaneously after Step 9 reports zero blocker issues."

There is no mention of setting `adversarial_review_triggered` in `state.yml` before dispatch — Step 9 in from-scratch.md only emits issue files; nothing flips the flag the adversarial-reviewer expects.

`review/index.md` Step 4 (Reviewer Dispatch):
> "Dispatch cross-reviewer and adversarial-reviewer in parallel."

Again, no flag-setting step. So under both entry points, the orchestrator dispatches adversarial-reviewer, which then immediately falls through to its no-op ACK path (Trigger Condition section) because the flag is absent. Result: adversarial-reviewer always returns empty, the entire attack-angle catalog (NFR realism, concurrency, failure modes, security, observability, schema evolution, ops readiness, authz model) is silently never executed.

This is CR-L11 — a contract declared in one file (adversarial-reviewer's trigger flag) is not honoured by the implementation in the orchestration files that dispatch it.

There are two consistent fixes:

(a) Drop the flag check from adversarial-reviewer entirely if the team's intent is "always run adversarial in parallel with cross". The cost is an opus dispatch every round, which the model-tier table accepts as `heavy`.

(b) Keep the flag and update from-scratch.md Step 10 + review/index.md Step 4b to write `adversarial_review_triggered: true` to `state.yml` before the parallel dispatch. The trigger predicate ("any in-generate critical or error issue") could then gate the write so adversarial actually skips when there's nothing to attack.

## Suggested Fix

Pick (a) or (b). If (a): remove the Trigger Condition section + no-op ACK form from `adversarial-reviewer-subagent.md`. If (b): add an explicit "set state.yml adversarial_review_triggered before dispatch" step to from-scratch.md Step 10 (gated on critical/error issue presence from Step 9) and to review/index.md Step 4 (always-true for `--review` since user-initiated reviews always want full attack coverage).
