# CR-L11

cross-reviewer's CR-D01..CR-D10 table is completely different from review-criteria.md's CR-D01..CR-D10 catalog

## Reasoning

`common/review-criteria.md` declares the canonical CR-D dimensions with these names:

- CR-D01 `responsibility-scoping`
- CR-D02 `nfr-decomposition`
- CR-D03 `error-handling-depth`
- CR-D04 `testability`
- CR-D05 `risk-coverage`
- CR-D06 `self-contained-files`
- CR-D07 `interface-protocols`
- CR-D08 `observability`
- CR-D09 `status-lifecycle-correctness`
- CR-D10 `prd-traceability`

`review/cross-reviewer-subagent.md` (Criteria Scope table, lines ~107–118) declares a completely different mapping for the SAME identifiers:

- CR-D01 = "Completeness"
- CR-D02 = "Consistency"
- CR-D03 = "Self-containment"
- CR-D04 = "Implementability"
- CR-D05 = "NFR coverage"
- CR-D06 = "Testability"
- CR-D07 = "Risk awareness"
- CR-D08 = "PRD interaction design alignment"
- CR-D09 = "Bootstrap self-sufficiency"
- CR-D10 = "Convention translation (semantic)"

This is the CR-L11 textbook example: a stated contract (review-criteria's CR catalog, which `run-checkers.sh` and the per-issue reviser consume) that contradicts the implementation in cross-reviewer-subagent. Every issue the cross-reviewer files will be tagged with a `criterion_id` that means one thing in the issue file and a different thing in the criteria catalog. The reviser, the summarizer, and `--diagnose` metrics will all mis-attribute findings.

The Domain-Specific Review Guidance section also references its own (wrong) CR-D mapping (e.g. "1. CR-D02 Consistency", "2. CR-D03 Self-containment") cementing the divergence.

## Suggested Fix

Replace the cross-reviewer's Criteria Scope table with the canonical CR-D01..CR-D10 names from `common/review-criteria.md`. Re-write the Domain-Specific Review Guidance numbered subsections so the CR-IDs in the headings match the canonical names. Severities, "what to check" prose, and the positive/negative examples can be kept — only the CR-ID-to-dimension binding needs to be re-aligned.
