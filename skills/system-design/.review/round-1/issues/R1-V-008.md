# CR-L11

SKILL.md mixes `.reviews/` (with S, --review mode) and `.review/` (no S, in-pipeline) without making the distinction clear; this is the load-bearing path that review/index.md, revise/index.md, and from-scratch.md all depend on

## Reasoning

The skill ships TWO distinct review-artifact directories at the same target root:

- `.reviews/` (with the `s`) — used by `--review` and `--revise` end-user flows. Contents: LINT-NNN.md, REVIEW-NNN.md, REVIEW-NNN-ADV.md, REVIEW-NNN.applied.md. Documented in `review/index.md` and `revise/index.md`.
- `.review/` (no `s`) — used by the in-pipeline harness during generate-mode loops. Contents: `round-<N>/issues/`, `round-<N>/self-reviews/`, `round-<N>/plan.md`, `versions/<N>.md`, `state.yml`, `traces/`. Documented in skill-forge guide §19.1 and from-scratch.md.

`review/index.md` "Distinction from Generate-Mode Review" section calls this out explicitly:
> "Never conflate these two paths. The `.reviews/` directory (user-facing, with capital S) is distinct from `.review/` (internal harness, no capital S)."

But `SKILL.md` is the single entry point and ITS coverage of the two paths is contradictory:

1. "Output Structure" diagram only shows `.reviews/` (with S):
   ```
   └── .reviews/              # Transient — not version-controlled
       ├── REVIEW-*.md / .applied.md   # Semantic findings (LLM reviewers)
       └── LINT-*.md / .applied.md     # Mechanical findings (structural-lint scripts)
   ```
   But it does not show `.review/` at all — yet from-scratch.md / new-version.md / revise/index.md / Bootstrap Precheck all rely on `.review/` to exist.

2. "Mode Routing" table says `--review` produces "LINT-*.md + REVIEW-*.md under `.review/round-<N>/issues/`" — that's the in-pipeline path, contradicting the actual `--review` mode definition in `review/index.md` which writes to `.reviews/`. The Mode Routing description is wrong on this row.

3. "Bootstrap Precheck" tells the orchestrator to write skill-root to `<target>/.review/state.yml` — using the no-S harness directory. This is correct but only for in-pipeline, not for `--review` mode where state.yml does not apply.

4. The "gitignore" hint at the bottom of Output Structure says `docs/raw/design/*/.reviews/` — only the with-S form, ignoring `.review/` which also needs gitignoring per skill-forge guide.

The orchestrator following SKILL.md as the single source of truth will fail in both directions: read SKILL.md → conclude only one directory exists; read review/index.md → conclude the SKILL.md Output Structure is missing a directory.

## Suggested Fix

Update `SKILL.md` to expose both directories explicitly:

1. In "Output Structure", add a `.review/` (no-S) tree alongside `.reviews/` and label them by mode of use ("in-pipeline harness, no S" vs "end-user review/revise output, with S").
2. In "Mode Routing" `--review` row, change the produced-path string to `.reviews/REVIEW-NNN.md` and `.reviews/LINT-NNN.md`.
3. Update the gitignore hint to add `docs/raw/design/*/.review/` alongside `.reviews/`.
4. Optionally add a one-paragraph "Two review directories" note borrowed verbatim from `review/index.md`'s table to anchor the distinction in the entry-point file.
