# CR-L11

from-scratch.md Step 7 references `common/skeleton/document/` as the scaffold source, but no such directory is documented in SKILL.md or common/

## Reasoning

`generate/from-scratch.md` Step 7 — Scaffold:
> "scripts/scaffold.sh <target>/ <target>/.review/round-0/clarification/<ts>.yml"
> "Outputs: full skeleton tree at <target>/ (copied from `common/skeleton/document/`)"

`SKILL.md` Configuration & Subagent Files section enumerates files under `common/`:
- `common/config.yml`
- `common/review-criteria.md`
- `common/domain-glossary.md`
- `common/templates/...`

It does NOT mention `common/skeleton/`. Listing of `skills/system-design/common/` confirms only `config.yml`, `domain-glossary.md`, `review-criteria.md`, `scaffold-provenance.yml`, `shared-scripts-manifest.yml`, `snippets.md`, and `templates/` exist — no `skeleton/` subdirectory.

If `scripts/scaffold.sh` actually consumes `common/skeleton/document/`, that path either lives at the parent skill-forge level (which the from-scratch.md should specify, since the system-design `scaffold.sh` is the local copy) or is a stale reference to a path that was never copied into system-design. Either way the from-scratch.md description does not match what's on disk in system-design.

This is a CR-L11 cross-reference: from-scratch.md declares a location that the file inventory in SKILL.md / common/ does not include.

Note: this finding is a `suggestion` rather than `important` because (a) Step 7 is a script invocation, not a sub-agent contract, so failure surfaces as a clear scaffold.sh error rather than silent breakage; (b) the actual `scripts/scaffold.sh` may resolve the path differently than the prose suggests. Still worth fixing the prose to keep the from-scratch.md self-consistent with the rest of the skill.

## Suggested Fix

Either:

(a) If `scripts/scaffold.sh` reads from a path under the parent skill-forge tree (not under system-design's own `common/`), update from-scratch.md Step 7 to make this explicit: "skeleton tree copied from `<skill-forge-root>/common/skeleton/document/`" (with the skill-forge root resolved via the skill-root: state.yml key written during Bootstrap Precheck).

(b) If the skeleton truly should live under system-design's own common/, add the directory and document it in SKILL.md's Configuration & Subagent Files section.

Pick (a) if scaffold.sh is shared infrastructure; pick (b) if the team intends every skill to ship its own skeleton.
