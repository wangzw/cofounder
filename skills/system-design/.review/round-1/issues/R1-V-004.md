# CR-L11

from-scratch.md Step 9 dispatches `revise/reviser-subagent.md` but the skill ships `revise/per-issue-reviser-subagent.md`

## Reasoning

`SKILL.md` "Configuration & Subagent Files" lists exactly one revise sub-agent prompt:
> "`revise/per-issue-reviser-subagent.md`"

`generate/from-scratch.md` Step 9 (Structural Lint Pre-pass) instructs the orchestrator:
> "If any `blocker` issues found → spawn reviser sub-agents (one per affected file, from `revise/reviser-subagent.md`)..."

The path `revise/reviser-subagent.md` does not exist on disk; only `revise/per-issue-reviser-subagent.md` exists. Any orchestrator that takes Step 9 literally will hit a file-not-found error on the lint-fix loop, which is exactly the path the two-phase quality gate is supposed to depend on.

This is a textbook CR-L11 cross-reference inconsistency: the from-scratch mode file declares a path that another file (SKILL.md inventory + the actual filesystem) implements differently. It also matches the CR-L11 rationale's "ID, count, or convention referenced in two places drifts because no script enforces consistency" phrase.

## Suggested Fix

Replace `revise/reviser-subagent.md` with `revise/per-issue-reviser-subagent.md` in Step 9 of `generate/from-scratch.md`. Grep the rest of the skill tree for any other occurrence of `reviser-subagent.md` without the `per-issue-` prefix and update them in the same pass.
