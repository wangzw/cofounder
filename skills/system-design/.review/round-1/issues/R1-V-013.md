# CR-D09

module-template's Status header field carries an Impl tri-state, but design-readme-template tracks design Status (Draft/Finalized/Implementing/Implemented) — the two are both legitimate dimensions per CR-D09 status-lifecycle-correctness, but the module-template confuses them

## Reasoning

`common/review-criteria.md` CR-D09 status-lifecycle-correctness:
> "Design-artifact Status values MUST use exactly: `Draft`, `Finalized`, `Implementing`, `Implemented` for document status; and `NotStarted`, `InProgress`, `Done` for implementation tracking."

`SKILL.md` Core Principles #9:
> "Status lifecycle — Design-level Status: `Draft → Finalized → Implementing → Implemented`. Module-level `Impl` column: `NotStarted → InProgress → Done`."

`common/domain-glossary.md` `Status lifecycle (design-level)` and `Impl tri-state (module-level)` define the two as INDEPENDENT — a module file should carry BOTH a design-level Status AND an Impl tri-state.

`common/templates/module-template.md` Header block:
> "> **Status:** NotStarted | InProgress | Done"
> "<!-- Status uses the Impl tri-state: NotStarted = not yet coded; InProgress = work underway; Done = merged to main. -->"

The template only carries Impl. Document-level Status (Draft/Finalized/Implementing/Implemented) — the dimension CR-D09 calls out first and the glossary declares MUST be present at design-level — is missing from the module file's header. Without it, you cannot tell whether a module spec is Draft or Finalized; you only know whether code exists.

`common/templates/design-readme-template.md` carries the design-level Status correctly (in the "Design Input" block: "Status: Draft | Finalized | Implementing | Implemented"), so the README is consistent. The drift is module-template-only.

This violates CR-D09 ("design-artifact Status values MUST use exactly Draft/Finalized/Implementing/Implemented for document status") because the module file is a design artifact and currently can't carry that status. Status assignments in different artifact files cannot be cross-checked.

## Suggested Fix

In `common/templates/module-template.md` header block, add a separate `**Doc Status:**` (or `**Design Status:**`) line alongside the existing `**Status:**` (impl tri-state). E.g.:

```
> **Doc Status:** Draft | Finalized | Implementing | Implemented
> **Impl Status:** NotStarted | InProgress | Done
> **Assignee:** {{assignee or "unassigned"}}
> **Source Features:** {{F-001, F-003}}
> **Complexity:** S | M | L | XL
```

Update the comment to clearly distinguish: "Doc Status tracks the design document's lifecycle; Impl Status tracks code progress. They are independent — a module can be `Doc Status: Finalized` and `Impl Status: NotStarted`." This matches the glossary entries already documenting both dimensions.
