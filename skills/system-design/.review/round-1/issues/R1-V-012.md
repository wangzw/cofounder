# CR-L11

design-readme-template's Module Interaction Protocols column set diverges from the column set the writer-subagent and X1 lint expect

## Reasoning

`common/templates/design-readme-template.md` Module Interaction Protocols section header:
> "| Interaction | Caller → Callee | Protocol | Idempotency | Retry Policy | Notes |"

`common/domain-glossary.md` `Module Interaction Protocols` term:
> "Columns: `Interaction`, `Caller → Callee`, `Method`, `Data Format`, `Error Strategy`, `Contract Test`."

`generate/writer-subagent.md` Leaf Type 3 (Design README) writer instructions reference X1 lint:
> "X1 lint (Module Interaction Protocols sync): every `(caller, callee)` dep pair from Module Index MUST have a corresponding row. Extra rows (no backing dep) MUST carry a cross-cutting note."

The X1 lint script (`scripts/check-module-deps-vs-protocols.sh` per CR-X1 review-criteria) checks deps↔protocols sync — i.e., presence of rows. But the column set divergence between the template (`Protocol | Idempotency | Retry Policy | Notes`) and the glossary (`Method | Data Format | Error Strategy | Contract Test`) means writers will produce a table with column names that the cross-reviewer's CR-D07 (interface-protocols) check will reject. CR-D07 in `review-criteria.md` reads:

> "every cross-module call MUST have an explicit protocol/contract stated in the Module Interaction Protocols table: sync/async classification, retry policy, and idempotency guarantee."

The template's columns (`Protocol | Idempotency | Retry Policy`) actually match CR-D07's three required dimensions better than the glossary's columns (`Method | Data Format | Error Strategy | Contract Test`). But the inconsistency means writers, reviewers, and the glossary all reference the same table by name and get three different column sets.

This is the same class of finding as R1-V-002 (API Surface columns drift) and R1-V-003 (Boundary Enforcement columns drift) — table column drift between template, glossary, and review criteria.

## Suggested Fix

Reconcile the three sources around a single canonical column set for Module Interaction Protocols. Recommended canonical set, taking the union of CR-D07 explicit requirements + glossary contract-test column:

`| Interaction | Caller → Callee | Sync/Async | Idempotency | Retry Policy | Contract Test |`

Update both `common/templates/design-readme-template.md` and `common/domain-glossary.md` to declare this column set. If the team prefers `Method | Data Format | Error Strategy` semantics, fold them into a `Protocol Detail` cell so the canonical contract dimensions (sync/async, idempotency, retry) stay first-class.
