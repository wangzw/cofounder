# CR-L07 — Adversarial-reviewer prompt body is unfilled DOMAIN_FILL stub with TODO placeholders

## Finding

`review/adversarial-reviewer-subagent.md` is shipped as a stub. Its Role-Specific Instructions block contains the placeholder marker and four open TODOs that were never filled in:

```markdown
<!-- DOMAIN_FILL: populated by writer-subagent during round 1 -->

**Role**: `reviewer` / `reviewer_variant: adversarial` (`V` in trace_id). Fires ADDITIONALLY
to the cross-reviewer when critical/error issues are found. Hunts for structural anti-patterns
specific to this skill's artifact domain.

<!-- TODO: define the attack angles specific to prd-analysis's artifact type -->
<!-- TODO: list the most likely failure modes introduced by this skill's generators -->
<!-- TODO: specify trigger conditions (must check state.yml adversarial_review_triggered) -->
<!-- TODO: describe no-op ACK behavior when trigger flag is absent -->
```

Per CR-L07 (`reviewer-prompt-discipline`), reviewer prompts MUST use normative language (`MUST`, `MUST NOT`, `FORBIDDEN`) and MUST describe the actual checks the reviewer performs. A prompt that consists of HTML-comment TODO placeholders provides zero normative guidance: a sub-agent dispatched against this prompt cannot determine which attack angles to hunt, when to trigger, or how to ACK. The result is non-deterministic adversarial review behavior — exactly the failure mode CR-L07 exists to prevent.

This also fails CR-L06 (`writer-prompt-quality-bar`) by extension: the prompt has no DO/DON'T examples for prd-analysis adversarial scenarios because the body is empty.

## Fix

Replace the entire DOMAIN_FILL/TODO block with normative content describing prd-analysis adversarial review. At minimum:

1. Trigger conditions — MUST read `state.yml.adversarial_review_triggered`; if absent or false, return ACK with empty `linked_issues` and write no issue files.
2. Attack angles specific to prd-analysis bundles — e.g., orphan features that pass CR-PP06 surface checks but lack semantic touchpoint coverage; cross-feature event flows where event names match but payload shapes diverge; design-token usage that survives CR-PP23 because the token is defined but is wrong type for the consuming context.
3. At least one positive (DO) and one negative (DON'T) example targeting prd-analysis.
4. ACK contract reaffirmation (single-line OK/FAIL).

Use the cross-reviewer-subagent.md "Domain-Specific Review Guidance" section as the structural template; mirror its level of specificity.
