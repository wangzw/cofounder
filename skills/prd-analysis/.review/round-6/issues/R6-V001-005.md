# R6-V001-005: common/templates/artifact-template.md is empty — DOMAIN_FILL placeholder remains, no template body

## Finding

`common/templates/artifact-template.md` retains the
`<!-- DOMAIN_FILL: populated by writer-subagent during round 1 -->` placeholder
(line 3) and four further `<!-- Writer: ... -->` instruction comments (lines 9, 13,
17, 21). The body has no actual template — just empty section headers
("Artifact Structure", "Required Fields", "Optional Sections", "Example") and an
instruction to fill them.

CR-L05 (artifact-template-self-contained) requires the artifact template to follow
the self-contained file principle and provide a concrete template structure. This
file fails that requirement at the most basic level: it has no template at all.

The skill ALREADY has rich, fully-realised templates at the skill root for each
artifact subtype:

- `prd-template.md` — README template
- `journey-template.md` — Journey template
- `feature-template.md` — Feature template
- `architecture-template.md` — Architecture index + topic templates
- `evolve-readme-template.md` — Evolve-mode README template

These templates demonstrate exactly what `common/templates/artifact-template.md`
should look like (fully self-contained, with inline copy rules, example rows,
GOOD/BAD anti-patterns). The empty file at `common/templates/artifact-template.md`
is a vestigial scaffold from skill-forge's skeleton that was never repurposed for
prd-analysis.

CR-S03 (directory-skeleton, structural) requires `common/templates/` to exist; an
empty placeholder at `artifact-template.md` may technically satisfy that, but
CR-L05 (semantic) fires on the lack of substantive content.

## Fix

Either:

1. Populate `common/templates/artifact-template.md` with a meta-index pointing to
   the four root-level templates (README/journey/feature/architecture), explaining
   when each applies and reproducing the self-containment rules they share. This
   creates a single navigation entry-point for the template family.
2. Delete `common/templates/artifact-template.md` (it has no incoming references
   from any of the 22 focus leaves I scanned) and rely on the four root-level
   templates directly. `from-scratch.md` Step 8 already routes writers to those
   templates by file class.

Option 1 is preferred because the skill-md-template.md sibling at
`common/templates/skill-md-template.md` is real and meaningful, so option 2 would
leave a half-filled `templates/` directory. Whichever option is chosen, the
DOMAIN_FILL placeholder + `<!-- Writer: ... -->` comments MUST be removed.
