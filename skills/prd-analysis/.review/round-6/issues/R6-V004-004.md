# Two conflicting review specs: top-level review-mode.md (legacy) describes a different orchestration model than review/index.md (canonical generative-skill model)

## Finding

The skill ships **two contradictory specs for `--review`**:

**Spec A — `review-mode.md` (skill root, ~700 lines, legacy interactive model):**

- Step 0 / 0.5 / 1 / 2 / 3: main agent does work directly. Step 1 (line 53–56)
  says: "The main agent MUST NOT read all journey / architecture topic /
  feature files itself" but THEN says "Read only: README.md, REVISIONS.md,
  architecture.md".
- Step 3 (line 95–): "Dispatch Parallel Review Subagents (LLM-type
  dimensions). Dispatch **one round** of subagents covering disjoint file
  sets, split by artifact class." This dispatches `general-purpose`
  subagents directly via the Agent tool — NOT `cross-reviewer-subagent.md`,
  NOT through the orchestrator → sub-agent IPC contract.
- No `cross-reviewer-subagent`, no `summarizer-subagent`, no
  `judge-subagent`, no `verdict.yml`, no `index.md`, no `dispatch-log.jsonl`.
  The legacy review mode is a single-pass main-agent operation that emits
  a markdown finding list directly.

**Spec B — `review/index.md` (skill subdirectory, ~130 lines, canonical model
per generative-skill design guide §3.9):**

- Steps 1–7: orchestrator runs `run-checkers.sh`, optionally short-circuits,
  dispatches `cross-reviewer-subagent.md` (reads `skip-set.yml`, writes
  issue files), conditionally dispatches `adversarial-reviewer-subagent.md`,
  dispatches `summarizer-subagent.md` (writes `index.md`), dispatches
  `judge-subagent.md` (writes `verdict.yml`), routes per verdict.
- Pure-dispatch orchestrator. No main-agent semantic work. All sub-agent
  output goes through the IPC contract.

These two specs are **incompatible**. They cannot both be correct. Yet
`SKILL.md` Mode Routing (line 19) advertises the review mode as loading
`review-mode.md, review-checklist.md, parallel-dispatch.md,
output-discipline.md` — i.e. the LEGACY spec. But the canonical scaffolding
(`scripts/check-skill-structure.sh`, `common/templates/skill-md-template.md`)
expects `review/index.md`.

This is a **CR-L04 (criteria-internally-consistent / cross-reference
consistency)** violation at the architectural-spec level — the skill cannot
decide what it is, and a coding agent reading SKILL.md to learn how `--review`
works will follow the legacy spec, which dispatches general-purpose agents
that do not write issue files in the form `judge-subagent` consumes.

The same problem exists for `revise-mode.md` vs `revise/index.md` and likely
for any `*-mode.md` file at the skill root (see also CR-S16 skeleton-
conformance flagging stray root-level `.md` files generally).

## Why this matters (skill-forge–specific anti-pattern)

The legacy `review-mode.md` predates the generative-skill architecture
introduced by skill-forge. When skill-forge regenerated prd-analysis (delivery
1–2 per `state.yml` notes), it added the canonical `review/index.md` but did
NOT delete or reconcile the legacy `review-mode.md`. The result is a
"layered orchestration" where the orchestrator's behavior depends on which
file the runtime loads first — non-deterministic across CC versions.

This was a documented failure mode in the prd-analysis delivery-1 audit
(per CR-S16's rationale: "skills accumulate stray root-level `.md` files
over their lifetime"). CR-S16 catches the **structural** problem (file
location), but the **semantic** consequence — two contradictory orchestration
specs co-existing — is a CR-L04 cross-reference inconsistency that no
script-tier check catches and no cross-reviewer in this round flagged.

The cross-reviewer issues R6-V001-001..006, R6-V002-001..003, R6-V003-001..006
all targeted file *contents* (DOMAIN_FILL stubs, broken bash, mislabeled
script args). None flagged the **architectural-level dual-spec drift**.

## Suggested fix

Decide which spec is canonical (per the generative-skill design guide §3.9
and the rest of the bundle's IPC contract, it MUST be `review/index.md`),
then:

1. **Delete `review-mode.md`** from the skill root, or relocate it to a
   `_legacy/` subdirectory with a clear header noting it is non-canonical
   reference material only.
2. **Update SKILL.md Mode Routing line 19** to load `review/index.md` (and
   remove `review-mode.md`, `review-checklist.md` from the loaded-files list
   for review mode — `review-checklist.md` is also a legacy artifact that
   conflicts with `common/review-criteria.md`).
3. **Apply the same treatment to `revise-mode.md`** vs `revise/index.md` —
   they have the identical dual-spec problem (see also R6-V004-003).
4. **Apply CR-S16 (skeleton-conformance) script-tier check** as the
   permanent guard.

Class-scan: I checked the other `*-mode.md` root files: `evolve-mode.md`,
`document-mode.md`, `questioning-phases.md`. They are all legacy-spec
documents predating the generative-skill model. Each is a candidate for the
same dual-spec finding, but I limit this issue to `review-mode.md` because
it has a direct canonical counterpart (`review/index.md`) on disk to
contradict against. The others may become similar issues once their
canonical counterparts ship.
