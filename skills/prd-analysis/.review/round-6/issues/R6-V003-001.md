# scaffold.sh `--help` documentation: placeholder anchors over-substituted into literal target values

## Finding

The `usage()` heredoc in `scripts/scaffold.sh` lines 24–28 documents the supported placeholder
names that callers must populate in their `clarification.yml`. In the skill-forge skeleton,
those lines read:

```
Supported placeholders in skeleton files:
  {{SKILL_NAME}}        The name of the skill
  {{ARTIFACT_ROOT}}     The artifact output root directory
  {{SKILL_VERSION}}     The skill version (e.g. 1.0.0)
  {{SKILL_DESCRIPTION}} The skill description (must start with "Use when")
```

In the prd-analysis target the same lines are now:

```
Supported placeholders in skeleton files:
  prd-analysis        The name of the skill
  docs/raw/prd/<YYYY-MM-DD>-<product-slug>/     The artifact output root directory
  0.1.0     The skill version (e.g. 1.0.0)
  Use when the user needs to create a Product Requirements Document, ... The skill description (must start with "Use when")
```

The four `{{...}}` anchors have been **substituted into their resolved target values**, leaving
the help text without the placeholder names a caller would actually need to learn. Anyone who
runs `scripts/scaffold.sh --help` on this target sees nonsense — they cannot tell what keys
their clarification YAML must declare. Worse, the line "prd-analysis        The name of the
skill" is not even valid markdown for the placeholder column — it conflates the placeholder
slot with the value, which has the literal effect of advertising the target's own name as the
"placeholder" callers should use.

This violates **CR-L04 (criteria-internally-consistent / cross-reference consistency)**: the
script's `usage()` text is intended to describe its substitution contract, but the substituted
text and the substitution machinery now describe contradictory contracts (the substitution
loop in the Python body still recognizes `{{SKILL_NAME}}` etc. — the doc just no longer
mentions them).

## Root cause

The `substitute_placeholders()` function (lines 134–141) runs over every text file in the
copied target tree, including `scripts/scaffold.sh` itself. The script does not exempt its
own source file from substitution, so its `--help` heredoc gets rewritten on every scaffold
run. The `NO_SUBSTITUTE` set (lines 89–92) only excludes `metrics-aggregate.sh` and
`lib/aggregate.py`; it does not protect `scaffold.sh`'s own self-documentation.

## Suggested fix

Two non-conflicting options:

1. **Add `scripts/scaffold.sh` to `NO_SUBSTITUTE`** so the script's own help text is preserved
   verbatim. This requires re-rendering the target's copy from the skeleton (post-fix
   scaffold runs will then carry the canonical help text).
2. **Quote-protect the placeholder examples** in `usage()` — e.g. write `\{\{SKILL_NAME\}\}` or
   wrap each anchor in a marker that `substitute_placeholders` is taught to ignore. Less
   robust because future placeholders would need the same treatment.

Option 1 is the cleaner fix and matches how `metrics-aggregate.sh` / `aggregate.py` are
already handled.
