# CR-L04 — Adversarial-reviewer Issue File Schema uses stale `issue_id:` key inconsistent with cross-reviewer's `id:`

## Finding

`review/adversarial-reviewer-subagent.md` (lines 56–69) defines its Issue File Schema as:

```yaml
---
issue_id: <target-slug>-round-<N>-<seq>
round: <N>
file: <target-relative-path>
criterion_id: <CR-ID>
severity: critical | error | warning | info
source: adversarial-reviewer
reviewer_variant: adversarial
status: new | persistent | resolved | regressed
---
```

The frontmatter key is `issue_id:` and the format is `<target-slug>-round-<N>-<seq>`.

However, the canonical sibling sub-agent `review/cross-reviewer-subagent.md` (lines 164–177) uses:

```yaml
---
id: R<N>-<seq>
round: <N>
file: <target-relative-path>
criterion_id: <CR-ID>
...
---
```

The frontmatter key is `id:` and the format is `R<N>-<seq>` — matching script-emitted issues from `run-checkers.sh` (§12.5). Round-3 issue R3-V004-001 already flagged and resolved this exact problem on `review/cross-reviewer-subagent.md`, but the adversarial-reviewer schema still carries the stale `issue_id:` key.

Per CR-L04 (`criteria-internally-consistent`), no two reviewer schemas in the same skill may use incompatible identifier conventions. Issue files written by the adversarial reviewer with `issue_id:` will be silently ignored by:

- `revise/index.md` Step 1 reads frontmatter `id`, not `issue_id` — adversarial issues are skipped from the open-issue list.
- `summarizer-subagent` aggregating round-N issues by `id`.
- Cross-reviewer status-progression tracking (`new → persistent → resolved`) which matches by `criterion_id + file` but uses `id` to deduplicate.

The discrepancy reproduces the same convergence-blocking defect that R3-V004-001 fixed on the cross-reviewer.

## Fix

Update `review/adversarial-reviewer-subagent.md` lines 56–69 to align with the canonical cross-reviewer schema:

```yaml
---
id: R<N>-<seq>
round: <N>
file: <target-relative-path>
criterion_id: <CR-ID>
severity: critical | error | warning | info
source: adversarial-reviewer
reviewer_variant: adversarial
status: new | persistent | resolved | regressed
---
```

Specifically:
1. Rename the key `issue_id` to `id`.
2. Replace the value template `<target-slug>-round-<N>-<seq>` with `R<N>-<seq>` (zero-padded 3-digit `<seq>`, starting at max existing in `round-<N>/issues/` + 1, per the cross-reviewer's matching guidance).
3. Reuse the cross-reviewer's wording around seq numbering to avoid future drift.
