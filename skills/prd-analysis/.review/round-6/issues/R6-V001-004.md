# R6-V001-004: in-generate-review.md DOMAIN_FILL placeholder remains AND CR Applicability table cites skill-forge CRs that do not exist in this skill's review-criteria.md

## Finding

`generate/in-generate-review.md` retains the placeholder
`<!-- DOMAIN_FILL: populated by writer-subagent during round 1 -->` (line 3) and the
writer-instruction comment
`<!-- Writer: populate with the CR-to-file-type mapping for this skill's domain -->`
(line 13). Worse, the CR Applicability Table (lines 14–21) cites criteria that do
NOT exist in this skill's `common/review-criteria.md`:

```
| File type        | Applies CRs                              | Severity floor                       |
|------------------|------------------------------------------|--------------------------------------|
| `SKILL.md`       | CR-S01, CR-S02, CR-S09, CR-L01           | critical for CR-S01/S02/S09          |
| `*-subagent.md`  | CR-S08, CR-L01, CR-L02                   | critical for CR-S08                  |
| `common/review-criteria.md` | CR-S05, CR-L03                | error                                |
| `common/config.yml` | CR-S06                                | error                                |
| Any artifact leaf | CR-L02                                  | error                                |
```

`common/review-criteria.md` for prd-analysis defines `CR-PP01`..`CR-PP51` plus the
single carryover `CR-S15`. `CR-S01..CR-S09`, `CR-L01..CR-L03` are skill-forge
meta-skill criteria — they are NOT defined here. A writer that follows this table
during in-generate self-review would either:

- Mark every row as PASS without grounding (no defined criterion to evaluate
  against), OR
- Throw a "criterion not found" error when the writer-subagent's self-review
  discipline tries to apply the table.

In either case the in-generate self-review is broken. CR-L02 is the right CR
because the prompt-side ACK contract demands a writer self-review with FAIL rows
that select a `blocker_scope` — but the writer cannot mark a FAIL row against a
non-existent CR. The data side of the ACK contract is broken.

This file appears to have been copy-pasted from a skill-forge skeleton without the
DOMAIN_FILL substitution that should have occurred during round 1 generation.

## Fix

Replace the entire CR Applicability Table with the prd-analysis CR set. The
authoritative mapping already exists in `generate/writer-subagent.md` lines 188–211
("CR Applicability by Leaf Type"). Either:

1. Copy that table into `in-generate-review.md` and remove the DOMAIN_FILL +
   `<!-- Writer: populate ... -->` placeholders; OR
2. Delete `in-generate-review.md` entirely and update `writer-subagent.md` to be
   the single source of truth (it already contains the same content) — `from-scratch.md`
   does not currently reference `in-generate-review.md`, so there's no broken link.

Option 1 keeps the file as a writer-facing checklist; option 2 removes a redundant
document. Either way the placeholders + skill-forge CR-IDs MUST go.
