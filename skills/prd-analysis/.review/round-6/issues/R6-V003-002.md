# git-precheck.sh: unquoted `this skill` value in `git -c user.name=...` breaks bootstrap commit

## Finding

`scripts/git-precheck.sh` lines 28–30 attempt to set git committer identity for the auto-init
bootstrap commit:

```bash
git -c user.name=this skill -c user.email=this skill@local \
  commit --allow-empty -m "init: this skill bootstrap" >&2 \
  || { echo "FATAL: initial commit failed" >&2; exit 1; }
```

The values `this skill` and `this skill@local` contain an embedded space and are
**unquoted**. Bash word-splits them before git sees the arguments, producing the argv:

```
git -c user.name=this skill -c user.email=this skill@local commit --allow-empty -m "..."
```

git parses `user.name=this` as the first `-c` value, then sees `skill` as a positional arg,
which it interprets as the (non-existent) git subcommand → `git: 'skill' is not a git
command`. The exit-status fallback then triggers `FATAL: initial commit failed` and the
whole precheck aborts with exit 1 — meaning **no skill that lands in a non-repo working
directory can ever pass `git-precheck.sh`**, defeating the auto-init affordance the script
exists to provide (per the §8.3 / §21.0 bootstrap contract).

This is a runtime-fatal bug. It violates **CR-L04 (cross-reference consistency)**: the
script's stated contract ("auto-init + bootstrap commit so downstream skill ops have a
parent commit") is contradicted by its actual execution path.

## Reproduction

```bash
mkdir /tmp/x && cd /tmp/x
bash /Users/wangzw/workspace/cofounder/skills/prd-analysis/scripts/git-precheck.sh
# → INFO: not a git repo; auto-running 'git init' + empty bootstrap commit
# → Initialized empty Git repository in /tmp/x/.git/
# → git: 'skill' is not a git command. See 'git --help'.
# → FATAL: initial commit failed
```

## Root cause

The skeleton at
`/Users/wangzw/.claude/skills/skill-forge/common/skeleton/document/scripts/git-precheck.sh`
ships the same defect on line 28 — this is an inherited bug, not a substitution accident.
Someone authored the skeleton intending the literal value `this skill` (a generic
placeholder phrase that survives the unsubstituted skeleton because no `{{...}}` was used),
but did not quote-protect the value when handing it to `git -c`.

## Suggested fix

Quote both `-c` arguments and the commit message. Either of:

```bash
git -c "user.name=this skill" -c "user.email=this skill@local" \
  commit --allow-empty -m "init: this skill bootstrap" >&2
```

or use a single-token identity:

```bash
git -c user.name=skill-bootstrap -c user.email=skill@local \
  commit --allow-empty -m "init: skill bootstrap" >&2
```

The fix MUST also be applied at the skeleton (`skill-forge/common/skeleton/*/scripts/git-precheck.sh`)
otherwise the next skill scaffolded will inherit the same broken precheck.
