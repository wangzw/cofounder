# CR-L07 — Per-issue-reviser prompt body is unfilled DOMAIN_FILL stub with TODO placeholders

## Finding

`revise/per-issue-reviser-subagent.md` is shipped as a stub. Its Role-Specific section contains the placeholder marker and four open TODOs that were never filled in:

```markdown
<!-- DOMAIN_FILL: populated by writer-subagent during round 1 -->

**Role**: `reviser` (`R` in trace_id). Scoped to ONE artifact leaf per dispatch. Reads all open
issues for that leaf, applies fixes, and writes the revised leaf.

<!-- TODO: describe domain-specific revision discipline for prd-analysis's artifacts -->
<!-- TODO: specify regression-protection protocol for this artifact type -->
<!-- TODO: describe skeleton-protection protocol -->
<!-- TODO: list any domain-specific forbidden revision patterns -->
```

The file does include a generic `### Revision Discipline` block with a few `FORBIDDEN` bullets, but the four DOMAIN_FILL TODOs (regression-protection protocol, skeleton-protection protocol, domain-specific forbidden patterns specific to prd-analysis) are still unaddressed. Per CR-L07, reviser prompts MUST use normative language and MUST describe the actual revision behavior expected. Leaving the placeholder TODOs in the prompt produces non-deterministic reviser behavior on prd-analysis artifacts — e.g., a reviser may not know that `architecture/design-tokens.md` token names must remain stable across revisions, or that journey ID changes require tombstone records.

## Fix

Replace the entire DOMAIN_FILL/TODO block with concrete, normative content describing prd-analysis revision discipline. At minimum:

1. **Domain-specific revision discipline** — e.g., "When fixing a feature leaf MUST preserve all touchpoint→feature back-references; if a back-reference is removed, MUST add a corresponding journey-leaf update issue." Reference the existing `revise-mode.md` Step 5 batch-by-file procedure as binding.
2. **Regression-protection protocol** — explicitly require reading the resolved-issues history (already mentioned in `revise/index.md` Step 3) and forbidding re-introduction of resolved issues; cite `regression_gate.max_injected_resolved` from `config.yml`.
3. **Skeleton-protection protocol** — list the protected paths (`scripts/metrics-aggregate.sh`, `scripts/lib/aggregate.py`, anything in the skeleton manifest) that the reviser MUST NOT touch. Already partially captured in the FORBIDDEN bullets, but should be made explicit per the TODO.
4. **Forbidden revision patterns specific to prd-analysis** — e.g., MUST NOT renumber Feature/Journey IDs (`F-NNN`, `J-NNN`); MUST NOT remove evidence rows or lower confidence labels; MUST NOT delete tombstone files in evolve-mode bundles.

Mirror the structural style of `review/cross-reviewer-subagent.md`'s Domain-Specific Review Guidance section.
