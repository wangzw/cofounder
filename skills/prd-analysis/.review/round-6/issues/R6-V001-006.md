# R6-V001-006: common/templates/artifact-template.md is empty — writer cannot honor any output contract derived from this template

## Finding

Same DOMAIN_FILL state as R6-V001-005, evaluated against CR-L02 (ACK contract
fidelity). When the writer sub-agent (`generate/writer-subagent.md`) is dispatched
to author a target file, the planner's `plan.md` `add[].template` field points the
writer at a template path. If a planner ever points at
`common/templates/artifact-template.md`, the writer would write a file whose body
is just the "Artifact Structure" / "Required Fields" / "Optional Sections" /
"Example" empty headers — i.e. a placeholder in production. The writer's ACK
return would be `OK self_review_status=FULL_PASS` (no FAIL rows because no CRs
apply to a placeholder skeleton), and the orchestrator would have no way to detect
the empty output.

This is the data-side ACK-contract violation: the file written to disk is not a
realised artifact, but the IPC contract has no signal that the writer's output is
unusable. CR-L02 governs the soundness of "Write to final path inside sub-session
+ Task return is one ACK line"; here the final-path write is hollow.

The fix is the same as R6-V001-005, but this issue is filed separately because
CR-L05 captures the template-quality dimension while CR-L02 captures the IPC /
contract dimension. Both fire on this same file with different remedy framings:
CR-L05 says "the template is non-substantive"; CR-L02 says "any writer dispatched
against this template breaks the IPC contract because their output is hollow".

## Fix

Either populate the file with a real template (option 1 of R6-V001-005), OR delete
it and ensure no `plan.md` entry references it (option 2). If the file is kept
empty, gate it: e.g. the planner-subagent prompt MUST refuse to emit a `template:
common/templates/artifact-template.md` row and the run-checkers script MUST flag
the placeholder as a CR-PP04-style "TBD" failure.

The simplest fix is option 2 (delete) plus a one-line update to
`generate/planner-subagent.md` ensuring its `add` examples never reference this
path.
