# R6-V001-002: domain-consultant-subagent.md has no DO / DON'T examples — quality bar absent

## Finding

`generate/domain-consultant-subagent.md` contains zero positive and zero negative
examples. The entire body (lines 46–62) is only the role declaration line plus four
TODO comments, then the ACK Format section. CR-L06 requires writer / authoring
sub-agent prompts to describe "what good output looks like" with at least 1
positive example (DO) and at least 1 negative example (DON'T / FORBIDDEN / BAD).

The domain-consultant is an authoring sub-agent — it produces a structured
`clarification.yml` artifact — and is therefore in scope for the quality-bar
requirement. Without examples, the consultant has no grounding for self-evaluating
its dialogue or its output, so the resulting `clarification.yml` shape will vary
across runs.

The sibling writer-subagent.md (lines 270–377) provides a strong template for what
this looks like done correctly: it shows GOOD/BAD touchpoint rows, GOOD/BAD AC
phrasing, GOOD/BAD design-token references, etc. The domain-consultant prompt
should follow the same pattern.

## Fix

Add at minimum:

1. **GOOD example** — a well-formed clarification dialogue snippet that produces a
   complete `clarification.yml` with all R-001..R-007 fields and the four flat
   placeholder keys filled with concrete values from the user's prompt.
2. **BAD example** — a dialogue / output that demonstrates a common failure mode,
   e.g. consultant fabricating answers the user did not provide (FORBIDDEN), or
   leaving R-001..R-007 with `status: deferred` when the user explicitly answered
   them inline.

Both examples should call out the specific CR or downstream consumer that the
positive form satisfies (planner reads R-001..R-007; writer reads
`SKILL_DESCRIPTION` for `description: "Use when …"`).
