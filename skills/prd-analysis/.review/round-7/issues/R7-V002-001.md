# R7-V002-001: Interaction Mode vocabulary drift — writer-subagent introduces a 10th value (`long-press`) that the glossary, journey-template, and per-issue-reviser all forbid

## Finding

`generate/writer-subagent.md` line 252-253 (in the journey-leaf section) instructs writers:

> Interaction Mode MUST be one of: `click`, `form`, `drag`, `swipe`, `long-press`, `keyboard`, `scroll`, `hover`, `voice`, `scan`.

This is a 10-value list including `long-press`.

Three other in-focus files declare a **9-value vocabulary** that does NOT include `long-press`:

1. `common/domain-glossary.md` line 13 — the authoritative glossary entry:
   > `interaction mode` | The primary input mechanism at a touchpoint: `click`, `form`, `drag`, `keyboard`, `scroll`, `hover`, `swipe`, `voice`, or `scan`

2. `common/templates/journey-template.md` line 90 — the touchpoint-row template column legend:
   > `{primary interaction pattern: click / form / drag / swipe / keyboard / scroll / hover / voice / scan}`

3. `revise/per-issue-reviser-subagent.md` lines 96-99 — the revision invariant (binding negative constraint):
   > **Interaction mode vocabulary is fixed.** Interaction mode values MUST be drawn exclusively from the project Glossary vocabulary: `click`, `form`, `drag`, `keyboard`, `scroll`, `hover`, `swipe`, `voice`, `scan`. The reviser MUST NOT introduce an unlisted interaction mode, even when paraphrasing a touchpoint description.

The reviser's invariant explicitly says "drawn exclusively from the project Glossary vocabulary". The glossary lists 9; the writer prompt mandates 10. Any writer that obeys writer-subagent.md line 252 and emits a touchpoint with `long-press` will be flagged by the reviser as a regression of CR-PP21 (`journey-interaction-modes`) and the reviser will be forbidden from preserving that value across a revision pass — even though the writer was instructed to emit it.

## CR-L11 reasoning

This is a textbook CR-L11 (cross-reference-consistency) violation per the criterion's fourth concrete pattern: "An ID, count, or convention referenced in two places drifts because no script enforces consistency." Here the convention is the **interaction mode vocabulary** referenced in four places (writer-subagent.md, domain-glossary.md, journey-template.md, per-issue-reviser-subagent.md), and the writer-subagent.md count differs (10 vs 9).

This is NOT a CR-L04 issue — CR-L04 is narrowly scoped to `conflicts_with` pairs in `review-criteria.md`.

## Distinct attack angle from R7-V001-001..003

The cross-reviewer (R7-V001-001..003) hunted dual-spec drift between `revise/revise-mode.md` and `revise/index.md` plus the missing `scripts/group-revise-issues.sh`. This issue is a **vocabulary-consistency drift** orthogonal to revise-mode scaffolding: an attribute value list that disagrees across four files. None of the cross-reviewer issues touch the interaction-mode vocabulary or any of the four files implicated here on this dimension.

Adversarial attack angle: skill-forge anti-pattern "ID, count, or convention referenced in two places drifts" — `long-press` is an unauthorized 10th token in writer-subagent's enumeration that no other artifact recognizes.

## Severity

`error` rather than `critical` because:
1. The dispatch loop is not blocked — writers obeying the 10-value list will produce touchpoints that pass writer self-review (CR-PP21 doesn't fire on `long-press` because writer-subagent.md endorses it) but fail any subsequent revise dispatch.
2. CR-PP21 is the per-criterion check for journey interaction modes; downstream the `long-press` value is a feature-touchpoint defect that surfaces as oscillation: writer adds it → reviser is forbidden from preserving it → regenerated touchpoint loses information that was specified.

## Suggested fix

Three coherent options, in decreasing order of preference:

1. **Drop `long-press` from writer-subagent.md line 252-253** — align with the glossary's authoritative 9-value list. Touchpoints that need a long-press distinction can be modeled via a `swipe`/`hover` mode plus a state-machine timing note (this matches the existing per-feature Interaction State Machine pattern).

2. **Add `long-press` to the glossary, journey-template.md, and per-issue-reviser-subagent.md** — promote the writer's enumeration to a 10-value vocabulary across all four files. This is the additive fix; it requires updating `domain-glossary.md` line 13, `journey-template.md` line 90, and `per-issue-reviser-subagent.md` lines 96-99 in the same revise dispatch so the four references stay aligned. Glossary-probe.sh would also need to recompute `glossary_hit` to include `long-press` if any prompt-time scoring depends on the term list.

3. **Add a CR-S* checker** that scans all four files and asserts the interaction-mode list is identical — close the loophole structurally so future drift is caught at script-tier rather than waiting for an LLM-tier reviewer to spot it. This is the long-term fix that R7-V002-001 alone does not solve; it should be filed as a separate scaffold issue against skill-forge.

Whatever option is chosen, the four references MUST be aligned in the same revise dispatch — an out-of-order revise (e.g., dropping `long-press` from writer-subagent only) leaves a 9-vs-9 alignment between writer and the others but leaves journey-template.md and per-issue-reviser-subagent.md unchanged, which is fine but writer-subagent's section on journey leaves loses one row that documented interaction-mode rationale; the reviser-subagent's assertion that the list is "drawn exclusively from the project Glossary" must continue to hold true.
