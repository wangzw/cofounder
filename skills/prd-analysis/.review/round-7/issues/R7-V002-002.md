# R7-V002-002: Reviser is instructed to 硬修 (force-fix in-place) `blocker_scope: global-conflict` issues, contradicting the writer-subagent contract and skill-forge's reviser-scope discipline

## Finding

`revise/per-issue-reviser-subagent.md` "Revision Discipline" section, lines 187-190:

```
- For issues with `blocker_scope: global-conflict` escalated by the cross-reviewer: apply the
  fix scoped to this leaf only. If fixing this leaf creates a new conflict in another leaf,
  create a companion issue for that leaf — do NOT attempt to fix the other leaf in this
  dispatch.
```

This instructs the reviser to **apply** a fix for a `global-conflict` issue, scoped to the assigned leaf. The reviser is supposed to "fix" it, just confined to its single-leaf scope.

But `generate/writer-subagent.md` lines 81-85 describes `global-conflict` as the OPPOSITE class of issue:

> **FORBIDDEN** to "硬修" (force-fix in-place) a `global-conflict` self-review FAIL — use the blocker-scope taxonomy, record the FAIL row with `blocker_scope: global-conflict`, and return `OK ... self_review_status=PARTIAL`. The cross-reviewer and reviser handle global conflicts in the review/revise loop (§11.2).

And the writer-subagent §3.9 contract block (line 67-70):

> Both the artifact leaf and the self-review archive are on disk. Downstream cross-reviewer / reviser handles the conflicts. This is the writer's normal success path when scope-external issues are found (§11.2).

The writer's contract is: a `global-conflict` is **scope-external** to a single leaf — it requires "cross-artifact view that is outside writer scope" (writer-subagent line 46). The writer punts to "the cross-reviewer and reviser handle" it. But the reviser-subagent says: "apply the fix scoped to this leaf only" — i.e., **the reviser also operates on a single leaf**, with the same scope as the writer. So no role in the loop has the cross-artifact view needed to actually resolve a global-conflict.

The skill-forge canonical adversarial-reviewer-subagent.md (`/Users/wangzw/.claude/skills/skill-forge/review/adversarial-reviewer-subagent.md` attack angle #6) makes this explicit:

> Check `revise/per-issue-reviser-subagent.md`: does it instruct the reviser to attempt resolving issues flagged with `blocker_scope: global-conflict` in-place? The correct behavior: emit a `CR-META-skip-violation` meta-issue and defer to HITL or a dedicated global-conflict resolution pass. Any language encouraging the reviser to "fix it anyway" is an anti-pattern.

The current per-issue-reviser-subagent.md language IS exactly the anti-pattern: "apply the fix scoped to this leaf only" + "create a companion issue for that leaf". This is "fix it anyway with a footnote" — the reviser has no more cross-artifact authority than the writer that produced the FAIL row.

## CR-L07 reasoning

CR-L07 (reviewer-prompt-discipline) is the closest match for reviser-prompt language anti-patterns; the skill-forge attack angle #6 explicitly flags this under CR-L07. The criterion's spirit is "reviewer/reviser prompts MUST use normative language for hard checks; soft language is FORBIDDEN". Here the language is technically normative ("apply the fix scoped to this leaf only") but the reviser is being assigned a contract it cannot fulfill — an inversion of the writer's hard-check posture into a reviser soft-edit. The result mirrors what soft-language language produces: under-reporting and mis-classification of hard blockers.

This is also CR-L11 cross-reference inconsistency between writer-subagent and per-issue-reviser-subagent on the same `blocker_scope: global-conflict` field. I tag it CR-L07 to preserve the skill-forge taxonomy for "reviser-scope-discipline" violations; a sibling CR-L11 issue is plausible but would duplicate the same cited evidence.

## Distinct attack angle from R7-V001-001..003

The cross-reviewer (R7-V001-001..003) hunted dual-spec drift in revise-mode files. This issue targets a **role-boundary inversion**: the reviser is being asked to do scope-external work that violates the writer-subagent's §11.2 contract. None of the cross-reviewer's three findings touch the global-conflict handling protocol or the role boundary between writer and reviser.

## Severity

`error` rather than `critical` because:
1. In practice, most cross-reviewer issues have `blocker_scope: cross-artifact-dep` or `input-ambiguity`, not `global-conflict` — the regression-rate at `global-conflict` is non-zero but bounded.
2. The "create a companion issue for that leaf" language IS escape-hatched (the reviser does emit a follow-up issue), but the framing is "fix and follow up" rather than "skip and escalate", which is the role-boundary inversion CR-L07 catches.
3. Critical-level escalation belongs to CR-L01/CR-L02 (orchestrator pure-dispatch / ACK-contract fidelity); this is a sub-agent-prompt language defect, not a dispatch-loop integrity defect.

## Suggested fix

Replace lines 187-190 of `revise/per-issue-reviser-subagent.md` with:

```
- For issues with `blocker_scope: global-conflict` escalated by the cross-reviewer: do NOT
  apply a fix in this dispatch. Emit a meta-issue at
  `<target>/.review/round-<N>/issues/<new-issue-id>.md` with
  `criterion_id: CR-META-skip-violation`, severity `critical`, and body referencing the
  global-conflict issue ID. Return `FAIL trace_id=<id> reason=global-conflict-requires-cross-artifact-pass`.
  Global conflicts are resolved via HITL escalation or a dedicated cross-artifact resolution
  pass — the per-leaf reviser scope is structurally incapable of resolving them.
```

This aligns the reviser's behavior with:
- The writer-subagent §11.2 contract (writer punts; reviser punts; HITL or cross-artifact pass resolves)
- The skill-forge canonical adversarial attack angle #6 (no 硬修 in single-leaf scope)
- The reviser's own Skeleton-Protection Protocol pattern (lines 156-174) — same posture (refuse + meta-issue + FAIL ACK) for skeleton-owned paths is already documented and self-consistent; global-conflict needs the same treatment.

The companion-issue mechanism (still useful for `cross-artifact-dep` scope, where the reviser CAN make scoped progress) stays in place — only the `global-conflict` case changes.
