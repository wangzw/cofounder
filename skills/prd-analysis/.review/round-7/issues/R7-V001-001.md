# R7-V001-001: revise/index.md references `scripts/group-revise-issues.sh` which does not exist

## Finding

`revise/index.md` Step 1 (lines 11-47) declares the orchestration step as:

```bash
bash scripts/group-revise-issues.sh <target> <N>
```

with detailed contract: "The script reads `<target>/.review/round-<N>/issues/` (frontmatter only), filters to open statuses (`new`, `persistent`, `regressed`), skips skeleton-owned paths, and emits a YAML manifest at `<target>/.review/round-<N>/revise-plan.yml`."

Line 96-97 reinforces the contract: "all of this is delegated to `scripts/group-revise-issues.sh`. The orchestrator only invokes the script and consumes its YAML output verbatim".

However, `scripts/group-revise-issues.sh` does NOT exist on disk:

```
$ ls /Users/wangzw/workspace/cofounder/skills/prd-analysis/scripts/group-revise-issues.sh
ls: ... No such file or directory
```

It is also not declared in `common/review-criteria.md` `script_path:` (auto-derived inventory wouldn't pick it up), nor in any other inventory or reference. The orchestrator that follows revise/index.md will fail with a script-not-found error on its first revise dispatch.

## CR-L11 reasoning

This is a textbook CR-L11 (cross-reference-consistency) violation per the criterion's third concrete pattern: "A stated contract in any artifact MUST agree with the implementation, list, or path it references in another artifact." The contract in revise/index.md ("invoke this script, consume its output") references an implementation that does not exist.

This is NOT a CR-L04 (criteria-internally-consistent) issue — that criterion is narrowly scoped to `conflicts_with` pairs inside `review-criteria.md`. The R6 round's CR-L04 over-tagging rationale is exactly what CR-L11 was added to address.

## Suggested fix

Either:
1. Create `scripts/group-revise-issues.sh` with the documented contract (read `round-<N>/issues/*.md` frontmatter, filter open statuses, skip skeleton paths via `shared-scripts-manifest.yml`, emit `revise-plan.yml`), and add it to `INFRA_SCRIPTS` in `check-scripts-inventory.sh` (or auto-derive via a CR declaration).
2. Or, if the script is intentionally deferred, replace Step 1 in revise/index.md with a placeholder that does NOT name the missing script, and mark the leaf as a dependency for the next delivery.

The first is preferred — option 2 leaves the revise loop fundamentally unimplemented.
