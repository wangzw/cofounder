# R7-V002-003: per-issue-reviser-subagent.md cites a `revise/index.md` Step 5 that does not exist — same dual-spec drift class as R7-V001-002, surfaced from a different file

## Finding

`revise/per-issue-reviser-subagent.md` line 184-186, in "Revision Discipline":

```
- Reference the `revise/index.md` Step 5 batch-by-file procedure as binding for orchestration
  context — each reviser dispatch is scoped to ONE leaf, and all open issues for that leaf
  are processed in the same write.
```

The reviser-subagent claims a binding `revise/index.md` Step 5 "batch-by-file" procedure. But `revise/index.md` only defines Steps 1–4 (line 11: "Step 1 — Build Issue-Group Manifest", line 49: "Step 2 — Fan-out Per-Issue-Reviser", line 65: "Step 3 — Summarizer", line 74: "Step 4 — Judge"). There is no Step 5.

The "Step 5 batch-by-file" content does exist — but in `revise/revise-mode.md` line 239-345 ("## Revise Step 5 — Execute Changes" → "### Batch by File (Required)"). That is the legacy interactive document, NOT the canonical generative-skill orchestration.

So the reviser-subagent is silently cross-referencing the legacy `revise-mode.md`, with the wrong file path (`revise/index.md`). When the orchestrator dispatches a reviser:

1. The reviser reads its own subagent.md.
2. Sees "Reference `revise/index.md` Step 5 batch-by-file procedure as binding".
3. Opens `revise/index.md`, finds only 4 steps, no batch-by-file procedure.
4. Either silently proceeds without the binding contract, or hunts in the (legacy) `revise-mode.md` and follows the wrong orchestration model — the legacy model is interactive (Clustering Subagent, Templates A/B), not the canonical per-issue model.

This is the same dual-spec drift class as R7-V001-002 (SKILL.md mode-routing for `--revise` pointing at `revise/revise-mode.md`), surfaced from the **per-issue-reviser-subagent.md side** of the contract. R7-V001-002 catches the orchestrator's entry-point referring to the wrong file; this catches the reviser's own contract referring to a Step that lives in the wrong file.

## CR-L11 reasoning

CR-L11 third concrete pattern: "A stated contract in any artifact MUST agree with the implementation, list, or path it references in another artifact." The reviser-subagent's stated contract ("Reference `revise/index.md` Step 5") references a step that does not exist at the cited path. The actual Step 5 lives in the rival `revise/revise-mode.md` file — exactly the dual-spec drift R7-V001-002 was filed against.

## Distinct attack angle from R7-V001-002

R7-V001-002 finds the SKILL.md → revise-mode.md path (orchestrator entry → legacy file). This issue finds a **second, asymmetric** cross-reference: a sub-agent prompt → `revise/index.md` Step 5 (legacy step). They are independent links in the dual-spec graph; resolving R7-V001-002 alone (e.g., by folding revise-mode.md content into revise/index.md and adding a Step 5) would not fix this issue's surface symptom unless the new index.md happens to have a Step 5 with the same anchor name. Likewise, fixing the reviser-subagent's reference (e.g., changing it to "Reference `revise/revise-mode.md` Step 5") would not fix R7-V001-002 — it would re-link the reviser to the legacy file and double down on the dual-spec drift.

The two issues only converge under one fix path: collapse the dual-spec drift entirely, then re-paint both references to the surviving file at the surviving step number.

## Severity

`error` — same severity as R7-V001-001 (the sibling missing-script issue). Critical was reserved for the SKILL.md mode-routing because it makes the entire generative-skill orchestration unreachable. This issue is a sub-agent contract drift; it leaves the reviser without binding orchestration context, which degrades reviser correctness but does not block the dispatch loop.

## Suggested fix

Coordinate with R7-V001-002 (revise-mode dual-spec collapse). Once revise-mode.md content is folded into revise/index.md (or a referenced sub-file under revise/), update `revise/per-issue-reviser-subagent.md` line 184-186 to point at the surviving Step number with the surviving file path. If revise/index.md grows a "Step 5 — Execute Per-Leaf Revision" section (or equivalent), the reference becomes accurate; if the procedure becomes the body of Step 2 (fan-out) instead, the reference must read "revise/index.md Step 2 fan-out contract" rather than "Step 5 batch-by-file".

If R7-V001-002 is resolved by deleting `revise/revise-mode.md` outright with no replacement of the Step 5 batch-by-file content (which is plausible — most of revise-mode.md Step 5 is an interactive Fix-subagent template, not directly applicable to per-issue-reviser fan-out), then the reviser-subagent reference must be deleted, not retargeted. The reviser already has the contract it needs in the canonical revise/index.md Step 2 ("Fan-out Per-Issue-Reviser") — the "binding orchestration context" for a per-leaf reviser is just "you are scoped to one leaf, all its open issues, single write". That is already in revise/index.md Step 2 lines 50-63 and is also restated in this same per-issue-reviser-subagent.md `Role` line 45-47. The line 184-186 reference is structurally redundant and was the legacy-doc compatibility shim.
