# R8-001: parallel-dispatch.md introduction perpetuates the legacy revise-mode terminology that R7-V001-002/R7-V001-003 retired

## Finding

`common/parallel-dispatch.md` lines 1-5 — the file's introductory paragraph — still describes
the file's purpose using legacy `revise/revise-mode.md` terminology that has been retired
from the canonical generative-skill orchestration:

```
# Parallel Dispatch Protocol

Shared dispatch rules for fan-out generation of feature/journey/architecture leaves (generation Step 3),
review subagents (review-mode Step 2), the clustering subagent (revise-mode Pre-Answered Mode), and
fix subagents (revise-mode Step 5). These rules take precedence over any per-mode wording that conflicts.
```

Two of the four cited use-cases reference legacy concepts that do NOT exist in the
canonical `revise/index.md` orchestration:

1. **"the clustering subagent (revise-mode Pre-Answered Mode)"** — Pre-Answered Mode and
   the Clustering Subagent are interactive-flow concepts from `revise/revise-mode.md`
   lines 11-78 (a 6-step interactive change-gathering flow with `subagent_type:
   "general-purpose"` clustering). Neither concept exists in the canonical generative-skill
   `revise/index.md` (which is a 4-step pure-dispatch flow: build manifest → fan-out
   per-issue-reviser → summarizer → judge). The "clustering subagent" pattern was retired
   when the generative-skill model replaced the interactive change-gathering model.

2. **"fix subagents (revise-mode Step 5)"** — "Fix subagents" is the legacy term used by
   `revise/revise-mode.md` Step 5 ("Execute Changes" with Templates A/B). The canonical
   `revise/index.md` Step 2 dispatches `revise/per-issue-reviser-subagent.md` instances —
   these are called "per-issue revisers", not "fix subagents". `revise/revise-mode.md` Step 5
   does not exist in the canonical orchestration the file is supposed to govern.

This is the same dual-spec drift class as R7-V001-002 (resolved this round in SKILL.md
line 20) and R7-V001-003 (resolved this round in parallel-dispatch.md line 134), but
surfaced from the file's introduction paragraph rather than the cited line. The line-134
fix in round-7 retargeted just one reference; the introduction's two stale references
were not in scope.

## CR-L11 reasoning

CR-L11 second concrete pattern: "A mode file (e.g. `review-mode.md` at the skill root) and
its canonical counterpart (e.g. `review/index.md`) ship two different orchestration models
for the same `--review` mode, so SKILL.md Mode Routing cannot point to a single source of
truth." Same here for revise mode: parallel-dispatch.md's introduction declares its
applicability to "revise-mode Pre-Answered Mode" and "revise-mode Step 5", which only exist
in `revise/revise-mode.md` — not in the canonical `revise/index.md` that SKILL.md
mode-routing now points to. A reader of parallel-dispatch.md who follows these references
to understand "what dispatches does this protocol cover?" gets routed to the legacy
orchestration, contradicting SKILL.md's declaration that `revise/index.md` is the canonical
revise entry point.

This is NOT a CR-L04 issue — CR-L04 covers `conflicts_with` pairs only.

## Severity

`error` rather than `critical` because the flow is still functional — the file's actual
content (Rules 1-8) is mode-agnostic and applies to any fan-out parallel dispatch. The
defect is in the *applicability narrative* of the introduction, not the rules themselves.
A reader following the legacy references to `revise/revise-mode.md` will find a file that
exists on disk but is no longer the canonical revise orchestration; this degrades clarity
and bakes in dual-spec drift.

## Suggested fix

Replace lines 4-5 of `common/parallel-dispatch.md` with terminology that matches the
canonical `revise/index.md` orchestration. One concrete rewrite:

```
Shared dispatch rules for fan-out generation of feature/journey/architecture leaves (generation
Step 3), review subagents (review-mode Step 2), and per-issue reviser subagents (revise-mode
Step 2 fan-out). These rules take precedence over any per-mode wording that conflicts.
```

This:
- Drops "the clustering subagent (revise-mode Pre-Answered Mode)" — that pattern is retired.
- Replaces "fix subagents (revise-mode Step 5)" with "per-issue reviser subagents (revise-mode
  Step 2 fan-out)" — matches `revise/index.md` Step 2's actual dispatch shape.

Lines 22, 48 ("Fix subagents across different file clusters are always independent" /
"**Fix subagents:** ≤3 target files per cluster") use "Fix subagent" as a general-purpose
term for any same-file-cluster sub-agent, which is fine in isolation but co-occurs with
the line 4-5 legacy references; consider whether to rename to "Reviser subagent" in the
same revise dispatch for vocabulary consistency. (Optional, less load-bearing than the
line 4-5 fix.)
