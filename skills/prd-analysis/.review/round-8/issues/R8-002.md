# R8-002: SKILL.md "Exception for revise-mode Step 2" carve-out describes the legacy interactive flow, not the canonical revise/index.md Step 2

## Finding

`SKILL.md` line 43:

> **Exception for revise-mode Step 2:** The main agent MAY read `README.md` in revise-mode
> Step 2 for the purpose of presenting a product overview to the user. `README.md` is
> treated as a navigation index (not a per-feature or per-journey leaf) — the same carve-out
> applies as in review-mode Step 1. The main agent MUST limit its reads to `README.md` only
> (no scanning journey or feature file contents in the main agent).

This carve-out describes a step where the main agent reads `README.md` to present a "product
overview to the user" — that maps to `revise/revise-mode.md` line 125 ("## Revise Step 2 —
Present PRD Overview"), the legacy interactive flow.

But after the round-7 R7-V001-002 fix, SKILL.md's mode-routing for `--revise` (line 20) now
points at `revise/index.md`, which defines a fundamentally different Step 2 (line 49):

> ### Step 2 — Fan-out Per-Issue-Reviser (parallel)
>
> Fan-out one `per-issue-reviser-subagent.md` per `groups` entry in `revise-plan.yml`. All
> dispatches are parallel …

The canonical Step 2 is a parallel fan-out of reviser subagents — there is no main-agent
read of `README.md` in canonical Step 2; in fact, the §5.1 pure-dispatch principle that
SKILL.md line 35 declares ("Forbidden: reading artifact leaves") would prohibit such a read.

So the line-43 carve-out either:
1. Refers to a step that no longer exists in the canonical orchestration (legacy
   `revise-mode.md` Step 2), making it a dangling exception to the pure-dispatch rule
   that has no canonical step to apply to; OR
2. Implicitly leaves `revise-mode.md` as the active revise flow (since only that flow has
   a Step 2 that requires this carve-out), partially undoing the R7-V001-002 mode-routing
   fix that put `revise/index.md` in charge.

Either reading is a CR-L11 cross-reference inconsistency. The cleanest reading, consistent
with `revise/index.md` Step 2 being pure fan-out, is that this carve-out is now stale and
should either be deleted or retargeted at whatever step actually requires the README read
(if any — possibly Step 1's grouping-script invocation, but that's the orchestrator
running a script, not reading README).

## CR-L11 reasoning

CR-L11 third concrete pattern: "A stated contract in any artifact MUST agree with the
implementation, list, or path it references in another artifact." SKILL.md's stated contract
("revise-mode Step 2 has main-agent README read carve-out") references a step
(`revise/index.md` Step 2 = Fan-out Per-Issue-Reviser) that does not match the contract.
The contract describes the legacy `revise/revise-mode.md` Step 2 ("Present PRD Overview"),
which mode-routing line 20 no longer points to.

This is NOT a CR-L04 issue — CR-L04 covers `conflicts_with` pairs only.

## Class-based scan note

This is the same dual-spec drift class as R7-V001-002 (resolved this round) and R8-001
(filed separately for parallel-dispatch.md). I grep'd all seven focus leaves for the
pattern; SKILL.md line 43 is the only additional in-focus instance of the same class.

R7-V001-002 fixed the mode-routing TABLE (line 20); this issue is a mode-routing CARVE-OUT
EXCEPTION (line 43) that still references the legacy step semantics. They are distinct
in-file references.

## Severity

`error` rather than `critical` because:
1. The carve-out is permissive ("MAY read README.md"), not mandatory — it does not force
   the orchestrator into the legacy flow on its own.
2. The pure-dispatch principle declared on line 35 is the binding rule; this exception is
   subordinate text. A reader who internalizes the line-35 forbidden list will follow it
   regardless of line-43 ambiguity.
3. Critical-level escalation belongs to CR-L01/CR-L02 (orchestrator pure-dispatch / ACK-
   contract fidelity), which protect the dispatch loop itself; this is a documentation
   inconsistency, not a dispatch-loop integrity defect.

## Suggested fix

Three options:

1. **Delete line 43 entirely.** If `revise/index.md` Step 2 is pure fan-out (no main-agent
   read), there is no need for a README carve-out in revise mode. The line-35
   forbidden list governs.

2. **Retarget the carve-out** at whichever canonical step (if any) actually needs the
   main-agent README read. If none of revise/index.md Steps 1-4 needs it, fall back to
   option 1.

3. **Keep the legacy interactive flow** as a separate sub-mode loaded conditionally from
   `revise/index.md` Step 0 (similar to R7-V001-002's "Pre-Step 0" suggestion that was
   not adopted). In that case, retarget line 43 at the new Step 0 or interactive sub-mode
   path. This is the most invasive option and likely beyond scope for a single revise
   dispatch.

Option 1 is preferred — it cleanly closes the CR-L11 gap without expanding the canonical
orchestration's surface.
