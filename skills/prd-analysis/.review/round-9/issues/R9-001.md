# R9-001: review/index.md cites stale CR-count ranges (CR-S01..CR-S12 / CR-L01..CR-L10) that no longer match the canonical review-criteria namespace

## Finding

`review/index.md` carries three stale CR-count cross-references that contradict the actual
criteria the cross-reviewer and script-tier checkers operate against:

1. **Line 20** — Phase B description claims:

   > **Phase B**: runs all 12 script-type checkers (CR-S01..CR-S12) against the target tree;

   The skill-forge canonical `common/review-criteria.md` (the authoritative criteria source
   the round-9 cross-reviewer dispatch references) defines CR-S01..CR-S17 — three additional
   structural criteria (CR-S15 skill-md-cost-control-sections, CR-S16 skeleton-conformance,
   CR-S17 checker-implements-declared-cr) have been added beyond the original CR-S12 cap.
   The target's own `common/review-criteria.md` carries CR-S15, CR-S16, and CR-S17 explicitly
   (lines 147, 177, 203). `scripts/run-checkers.sh` Phase B does NOT hardcode "12" — it
   iterates every script-type criterion returned by `extract-criteria.sh`, so the count
   floats with the criteria file. The "12 script-type checkers (CR-S01..CR-S12)" phrasing
   in `review/index.md` line 20 understates the actual checker count and freezes a stale
   CR-ID range.

2. **Line 69** — Step 3 cross-reviewer dispatch description claims:

   > leaves listed in `skip-set.yml cross_reviewer_focus`, previous-round issue
   > frontmatter from `round-<N-1>/issues/`, writer self-review files at
   > `<target>/.review/round-<N>/self-reviews/`, and `common/review-criteria.md` (CR-L01..CR-L10).

   The canonical skill-forge `common/review-criteria.md` defines CR-L01..CR-L11 — eleven
   LLM-type criteria, not ten. The most recent addition (CR-L11 cross-reference-consistency)
   is the criterion under which this very issue is filed; its rationale field explicitly
   notes "Round-6 audit found 11 of 21 LLM-tier issues mis-tagged as CR-L04 because no
   broader cross-reference criterion existed" — confirming the count is 11, not 10.

3. **Line 127** — "Files in This Directory" listing claims:

   > [cross-reviewer-subagent.md](cross-reviewer-subagent.md) — Cross-reviewer sub-agent prompt (LLM-type criteria CR-L01..CR-L10)

   Same stale "CR-L01..CR-L10" range. The cross-reviewer's actual scope per the canonical
   role spec is all 11 LLM-type criteria (CR-L01..CR-L11).

## CR-L11 reasoning

CR-L11's fourth concrete pattern names this defect explicitly:

> An ID, count, or convention referenced in two places (e.g. "10 LLM-type criteria" in
> cross-reviewer-subagent.md vs the actual 11 in review-criteria.md after this addition)
> drifts because no script enforces consistency.

`review/index.md` line 20 declares "12 script-type checkers (CR-S01..CR-S12)" while the
canonical criteria namespace is CR-S01..CR-S17 (17 entries; the target's review-criteria.md
includes CR-S15, CR-S16, CR-S17 inline). Lines 69 and 127 declare "CR-L01..CR-L10" while
the canonical CR-L namespace is CR-L01..CR-L11. Both are CR-L11 cross-reference-consistency
defects — IDs/counts referenced in `review/index.md` that disagree with the implementation
in `common/review-criteria.md` (and the skill-forge canonical reference). A reader of
`review/index.md` who follows these references to understand "what does the cross-reviewer
audit?" gets a strict subset of the actual CR namespace; CR-L11, CR-S15, CR-S16, CR-S17
fall off the documented surface even though they are live and dispatched against.

This is NOT a CR-L04 issue — CR-L04 is restricted to `conflicts_with` oscillation pairs
inside `review-criteria.md`.

## Severity

`error` rather than `critical` because:

1. The numeric drift does not break the dispatch loop — `run-checkers.sh` Phase B iterates
   the actual criteria, and the cross-reviewer-subagent.md (skipped this round, but the
   canonical role spec) cites all 11 LLM criteria. So the live behaviour is correct; the
   defect is purely in the documentation surface of `review/index.md`.
2. Critical-level escalation belongs to CR-L01/CR-L02 (orchestrator pure-dispatch /
   ACK-contract fidelity), which protect the dispatch loop itself; this is a documentation
   inconsistency, not a dispatch-loop integrity defect.
3. The defect does, however, materially mislead operators reading `review/index.md` to
   audit what the review mode covers — they would conclude CR-L11 / CR-S15 / CR-S16 /
   CR-S17 are out of scope when in fact they are live. That degrades the index's value
   as a navigation surface.

## Class-based scan

I grep'd all five focus leaves (`SKILL.md`, `common/parallel-dispatch.md`,
`review/index.md`, `scripts/build-depgraph.sh`, `scripts/run-checkers.sh`) for CR-count
range patterns: `CR-L01\.\.CR-L10`, `CR-S01\.\.CR-S12`, "10 LLM", "12 script-type",
and the broader pattern `CR-(L|S)[0-9]+`. The only hits inside focus leaves are the
three lines in `review/index.md` listed above (lines 20, 69, 127). The other four
focus leaves carry no CR-ID range references.

`scripts/run-checkers.sh` line 643 mentions "CR-S*" generically (`# a prior CR-S* issue's
(criterion_id, file) does not appear in this round's findings`) — that is a wildcard
namespace reference, not a frozen count, and is correct as-written.

## Suggested fix

Replace the three stale CR-count phrasings in `review/index.md` with namespace-only
references that survive criteria additions:

- **Line 20**: drop the parenthetical numeric range entirely. Recommended rewrite:

  > **Phase B**: runs all script-type checkers (every entry with `checker_type: script`
  > in `common/review-criteria.md`) against the target tree;

- **Line 69**: drop the parenthetical numeric range. Recommended rewrite:

  > leaves listed in `skip-set.yml cross_reviewer_focus`, previous-round issue
  > frontmatter from `round-<N-1>/issues/`, writer self-review files at
  > `<target>/.review/round-<N>/self-reviews/`, and `common/review-criteria.md`
  > (every entry with `checker_type: llm`).

- **Line 127**: drop the parenthetical numeric range. Recommended rewrite:

  > [cross-reviewer-subagent.md](cross-reviewer-subagent.md) — Cross-reviewer sub-agent
  > prompt (all LLM-type criteria — `checker_type: llm` in `common/review-criteria.md`)

This phrasing keeps `review/index.md` correct as the criteria namespace evolves; further
additions (e.g. CR-L12) automatically remain in scope without re-editing this file.
