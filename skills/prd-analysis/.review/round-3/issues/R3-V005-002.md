# R3-V005-002: revise-mode Pre-Answered Mode reads .reviews/REVIEW-*.md which review-mode never writes

## Finding

`revise-mode.md` Pre-Answered Mode (lines 13, 19, 24) looks for `{PRD-dir}/.reviews/REVIEW-*.md` files, describing them as "produced by `--review` Step 4". However, `review-mode.md` Step 5 writes individual issue files to `{PRD-dir}/.review/round-N/issues/<issue-id>.md` — it does not produce any file at `.reviews/REVIEW-*.md`. Step 4 of review-mode is the cross-file check pass that aggregates findings; it also does not write a REVIEW file. As a result, `revise-mode.md`'s Pre-Answered Mode can never find the REVIEW file it expects, causing the Pre-Answered fast-path (Template A dispatch) to silently fall back to interactive mode (Template B) on every `--revise` invocation after a `--review`.

## Fix

Update `revise-mode.md` Pre-Answered Mode to consume the canonical output of `review-mode.md`: the individual issue files under `.review/round-N/issues/`. Change the Pre-Answered Mode header and flow as follows:

- Line 13: Change `{PRD-dir}/.reviews/REVIEW-*.md` to `{PRD-dir}/.review/round-<N>/issues/` and update the description to "produced by `--review` Step 5".
- Line 19 (Step 1): Replace "list `{PRD-dir}/.reviews/REVIEW-*.md`" with "list `{PRD-dir}/.review/round-*/issues/I-*.md` — pick the highest round-N directory whose issues/ subdirectory is non-empty".
- Remove the `.reviews/REVIEW-{timestamp}.applied.md` rename step (line 24) and replace with a mechanism that marks the consumed round as "applied" (e.g., creating a `.review/round-N/issues/.applied` sentinel file).
- Update Template A dispatch (lines 267–290) to point Fix subagents at the individual issue files rather than a monolithic REVIEW file, or aggregate the issue files into a compact manifest via the Clustering Subagent before dispatch.
