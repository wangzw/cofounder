# CR-L02 — feature-template instructs citation of source file paths in Relevant Conventions, violating self-containment

## Finding

`feature-template.md` lines 25–36 instruct writers to copy conventions inline from specific named files:

> "- *Coding conventions* (error handling, logging, concurrency policies relevant to this feature) — from `architecture/coding-conventions.md`"
> "- *Test isolation* ... — from `architecture/test-isolation.md`"

However, line 21 above this section also says:

> "**Relevant architecture:** {only the parts of the architecture this feature touches — 3–5 lines. Copy inline from architecture topic files; **do not reference them by path**}"

The Relevant Conventions sub-bullets cite file paths (`architecture/coding-conventions.md`, `architecture/test-isolation.md`, etc.) as source identifiers. The Key Rules (line 368) state: "Never say 'see architecture.md' or 'see J-001'. Cross-references for navigation are permitted but must NOT be load-bearing."

The template text is ambiguous: the bulleted "from `architecture/coding-conventions.md`" reads as a path reference rather than a provenance label, potentially leading writers to write "see `architecture/coding-conventions.md`" instead of copying the relevant text inline.

## Impact

Writers may interpret the "from `file.md`" syntax as an instruction to reference rather than copy, producing feature files with load-bearing file path references that violate the self-contained principle (CR-L02).

## Fix

Rephrase the Relevant Conventions bullets to make copy-intent unambiguous, e.g.: "Coding conventions (error handling, logging — copy applicable text inline; source: `architecture/coding-conventions.md`)". Add a parenthetical note at the top of the Relevant Conventions block: "Copy applicable text inline. Do not write 'see <file>' — the file paths below identify source documents only."
