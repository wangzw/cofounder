# CR-L04 — Journey Context touchpoint copy table in feature-template drops the `Emotion` column

## Finding

`journey-template.md` defines the canonical touchpoint table with 9 columns including `Emotion`:

```
| # | Stage | User Action | System Response | Screen/View | Interaction Mode | Emotion | Pain Point | Mapped Feature |
```

`feature-template.md` line 53 instructs writers to "copy from journey file" but defines a truncated 6-column table:

```
| Stage | Screen/View | Action | Interaction Mode | System Response | Pain Point |
```

The `Emotion` column (and `#` numbering) are stripped. This breaks CR-L04 cross-reference alignment: the feature's inline touchpoint copy does not faithfully reproduce the journey's canonical format, so a reader comparing the journey file to the feature's Journey Context section sees a structural discrepancy. Additionally, column order differs (`Action` vs `User Action`, `System Response` moved).

## Impact

Emotional states recorded in journey files — which drive UX decisions and priority per journey-template Key Rules — are lost when copied into feature files. This weakens self-containment and creates a silent data-loss pattern writers won't notice.

## Fix

Align the feature-template's touchpoint copy table with journey-template's canonical format: add `#`, `Emotion`, and rename `Action` → `User Action`; match column order. At minimum add `Emotion` since journey-template's Key Rules explicitly call it out as mandatory for UX decisions.
