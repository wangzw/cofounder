# CR-L07 — `long-press` interaction mode in journey-template is absent from project Glossary

## Finding

`journey-template.md` line 90 lists `long-press` as a valid Interaction Mode:

> `{primary interaction pattern: click / form / drag / swipe / long-press / keyboard / scroll / hover / voice / scan}`

The project Glossary in `CLAUDE.md` defines the canonical Interaction Mode list as:

> `click, form, drag, keyboard, scroll, hover, swipe, voice, scan`

`long-press` is not in the Glossary definition. This is a CR-L07 terminology inconsistency between the journey-template's enumeration and the authoritative Glossary. The review-checklist "Journey interaction mode coverage" dimension checks consistency between journey touchpoints and feature component contracts but doesn't catch the upstream mismatch between the template's mode list and the Glossary.

## Impact

Writers may use `long-press` in journey files based on the template example. The review dimension will not flag it since it is present in the template, but system-design and autoforge agents relying on the Glossary definition will not recognize `long-press` as a defined mode.

## Fix

Either add `long-press` to the Glossary Interaction Mode definition in CLAUDE.md, or remove it from the journey-template's example enumeration and replace with `swipe` (which covers the same mobile gesture intent and is already in the Glossary).
