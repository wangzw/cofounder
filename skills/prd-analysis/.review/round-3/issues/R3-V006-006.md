# CR-L09 — prd-template Feature Index has no scaffolding for auto-derived Dev/Deployment Infrastructure features

## Finding

`review-checklist.md` lines 109–110 define two Critical cross-file dimensions:

- **Development infrastructure feature**: a P0/Phase 1 feature named "Development Infrastructure" must exist, with no journey dependency, covering all convention section deliverables.
- **Deployment architecture completeness**: a "Deployment Infrastructure" feature must exist with deliverables for each deployment aspect.

Neither `prd-template.md` nor `feature-template.md` provides any scaffolding, placeholder, or instructional note for these auto-derived features. The Feature Index in prd-template.md is generic (`F-001`, `F-002` examples only). Writers generating a PRD from the template receive no signal that these two specific infrastructure features are mandatory.

## Impact

Writers following prd-template.md without also reading review-checklist.md will produce PRDs lacking both infrastructure features. These are Critical-severity review findings, meaning PRDs are likely to fail the first review on this dimension consistently — a structural template gap causing predictable, recurring review failures (CR-L09: template section not covered by checklist, inverted: checklist requirement not covered by template).

## Fix

Add a note in prd-template.md's Feature Index section (after the table definition) stating: "Two features are always auto-derived and must appear in the Feature Index as P0/Phase 1 regardless of the product: (1) Development Infrastructure — one requirement per architecture convention section, no journey dependency; (2) Deployment Infrastructure — one requirement per deployment architecture aspect, no journey dependency." Optionally add commented placeholder rows.
