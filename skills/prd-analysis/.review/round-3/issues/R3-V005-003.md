# R3-V005-003: document-mode.md activation trigger uses --document flag absent from SKILL.md routing

## Finding

`document-mode.md` § "When to Activate Document-Mode" (line 14) specifies: "Activate this mode when the user invokes the skill with `--document <path>`". However, SKILL.md's `## Mode Routing` table (line 17) and `## Input Modes` (line 45) show no `--document` flag. Document-based mode is triggered by supplying a positional path argument (`/prd-analysis path/to/notes.md`) — there is no `--document` flag defined anywhere in SKILL.md. The activation condition in document-mode.md references a flag that does not exist in the routing table, making the "When to Activate" section inconsistent with actual invocation.

## Fix

Update `document-mode.md` § "When to Activate Document-Mode" (lines 14–17) to align with SKILL.md's actual routing. Replace:

> "Activate this mode when the user invokes the skill with `--document <path>` or explicitly hands over a file"

with:

> "Activate this mode when the user invokes the skill with a positional path argument (`/prd-analysis path/to/notes.md`) pointing to an existing document, or explicitly hands over a file (brainstorm notes, user-story map, raw requirements doc, Notion export, etc.) and asks to derive a PRD from it. The trigger is the presence of a path argument to a non-PRD file — not a `--document` flag."
