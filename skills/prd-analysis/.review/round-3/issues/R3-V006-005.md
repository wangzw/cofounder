# CR-L09 — No review dimension covers evolve-mode-specific README structures

## Finding

`evolve-readme-template.md` defines three structural sections that are unique to evolve-mode PRDs and have no corresponding dimension in `review-checklist.md`:

1. **ID-Stability Ledger** (lines 147–159) — tracks all ID assignments across the version chain; includes rules that IDs are never reused and new IDs must be greater than baseline max.
2. **Cascade-Impact Map** (lines 161–173) — documents all cross-leaf propagations triggered by the iteration's changes.
3. **Deprecated-Item Tombstone Index** (lines 132–140) — cumulative index of all deprecated items across the version chain.

The `review-checklist.md`'s `Version integrity` dimension (line 113) covers predecessor path resolution and `→ baseline` link correctness, but does NOT check for presence, completeness, or correctness of these three evolve-mode sections.

## Impact

An evolve-mode PRD can pass all review dimensions while omitting the Cascade-Impact Map entirely (leaving undetected cascades) or providing an incomplete ID-Stability Ledger (allowing ID reuse). These are CR-L09 gaps: the review-checklist does not cover all sections defined in the template.

## Fix

Add an `Evolve-mode structural completeness` dimension to the review-checklist (scope: Cross-file, severity: Critical for evolve-mode, N/A for initial) checking: ID-Stability Ledger present and IDs never reused; Cascade-Impact Map present with all changed leaves listed; Deprecated-Item Tombstone Index present and covers all deprecated items in the version chain.
