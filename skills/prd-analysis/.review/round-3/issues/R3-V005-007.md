# R3-V005-007: revise-mode orchestrator reads PRD artifact leaf (README.md) in Step 2

## Finding

`revise-mode.md` Step 2 — "Present PRD Overview" (line 124) — instructs: "Read README.md in parallel with a quick scan of journey filenames." SKILL.md `## Core Contract` (line 35) states "Orchestrator is **pure dispatch + bookkeeping only**. Forbidden: reading artifact leaves." SKILL.md `## Forbidden Actions` (line 195) lists "Reading artifact leaves — no reading of `<artifact-path>` content; those paths belong to sub-agents." `README.md` in the PRD directory is a primary artifact leaf — it is generated output, not an index/navigation file within the skill directory. Reading it directly in the orchestrator (main agent) running revise-mode violates the Core Contract. This is a distinct issue from R3-V005-004 (review-mode): it covers the revise-mode path, where the read is interactive (Step 2 summarises content to the user), making it a more persistent pattern.

## Fix

Update `revise-mode.md` Step 2 to delegate the read + summarise task to a light-tier subagent rather than performing it in the main agent. Replace the Step 2 instruction with:

"Dispatch a `light`-tier summariser subagent to read `README.md` and produce a compact (≤10-line) product overview (name, vision, persona count, journey count, feature count by priority). Consume the summary — do NOT read README.md in the main agent. This keeps the main agent's context budget free for the multi-turn Step 3–5 dialogue."

If the Core Contract exception carve-out from R3-V005-004 is accepted (allowing index file reads), update Step 2 to clarify README.md is treated as a navigation index, not a leaf, and cap reads to README.md only (no scanning journey file contents in the main agent).
