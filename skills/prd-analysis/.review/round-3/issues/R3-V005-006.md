# R3-V005-006: "prefer" used in a hard dispatch rule context in review-mode.md

## Finding

`review-mode.md` Step 3 dispatch rules (line 99) reads: "if a subagent's findings are vague, prefer `--revise` over re-reviewing." CR-L07 requires that reviewer prompts use normative language (`MUST`, `MUST NOT`, `FORBIDDEN`) for hard checks and prohibits soft language (`try to`, `prefer`, `ideally`) for anything that must be enforced. While this sentence appears in the orchestrator dispatch rules (not strictly in a reviewer subagent prompt), it governs how the orchestrator reacts to subagent findings and is part of the document loaded as reviewer context. The use of "prefer" here is actionable guidance — an orchestrator following this file can treat "prefer" as optional, potentially re-dispatching a second review pass instead of routing to `--revise`. This creates non-deterministic dispatch behaviour.

## Fix

On line 99, replace: "if a subagent's findings are vague, prefer `--revise` over re-reviewing."

with: "if a subagent's findings are vague, MUST route to `--revise` — re-reviewing the same files is FORBIDDEN."
