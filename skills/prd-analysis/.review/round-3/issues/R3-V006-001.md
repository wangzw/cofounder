# CR-L07 — Example token `spacing.64` in feature-template is undefined in architecture-template

## Finding

`feature-template.md` line 121 uses `spacing.64` as an example layout token:

> `"two-column layout, sidebar width \`spacing.64\`, main content area with \`spacing.6\` padding"`

However, `architecture-template.md`'s Design Token System table defines spacing only up to `spacing.16` (64px). There is no `spacing.64` token. This creates a terminology inconsistency (CR-L07): the example token does not exist in the authoritative token table, so a writer generating output from this template may produce a feature file referencing a non-existent token.

## Impact

Writers following the example literally will cite `spacing.64` in feature Interaction Design sections, which then fails the "Design token completeness" review dimension (no raw values; token must exist). Downstream coding agents will also fail to resolve the token.

## Fix

Replace the example `spacing.64` with a defined token, e.g. `spacing.16` (64px), or add `spacing.64` to the architecture-template spacing table with an appropriate value (e.g. 256px).
