## Symptom

`generate/writer-subagent.md`'s "What a well-formed journey leaf looks like" section mandates
an 8-column touchpoint table (including "Emotion" and "Mapped Feature" columns) and requires
"Trigger", "Frequency", "Alternative Paths", "E2E Test Scenarios", and "Journey Metrics"
sections — none of which appear in `common/templates/journey-template.md`. A writer dispatched
to author a journey leaf will receive contradictory structural specifications.

## Evidence

**writer-subagent.md** (lines 283–295) mandates this for journey leaves:

```
1. Header (# J-NNN: Journey Name + Persona, Trigger, Goal, Frequency)
2. Journey Flow (Mermaid flowchart — NO ASCII art)
3. Touchpoints table (all 8 columns: #, Stage, User Action, System Response, Screen/View,
   Interaction Mode, Emotion, Pain Point, Mapped Feature)
4. Alternative Paths
5. Error & Recovery Paths
6. E2E Test Scenarios (for multi-touchpoint journeys)
7. Journey Metrics
```

**journey-template.md** defines these H2 sections:

```
## Persona
## Goal
## Pre-conditions
## Touchpoint Table
## Mapped Features
## Post-conditions
## Failure / Off-Path Handling
## Cross-Journey Connections
## Open Questions
## Change Log
```

**Touchpoint table column mismatch** — journey-template.md touchpoint table (line 46 of template):

```
| Step | Stage | Screen / View | Action | Interaction Mode | System Response | Pain Point |
```

This is 7 columns. writer-subagent.md says "all 8 columns" including "Emotion" and
"Mapped Feature". Neither "Emotion" nor "Mapped Feature" appear as touchpoint table columns
in journey-template.md.

**Header field mismatch** — journey-template.md frontmatter (lines 13–22 of template):

```yaml
id: J-NNN
slug: {journey-slug}
title: {Journey Title}
persona: {persona-name}
goal: {one-sentence outcome the persona pursues}
priority: P0 | P1 | P2 | P3
status: draft | accepted | implemented | deprecated
mapped_features: [F-NNN, F-MMM]
created: YYYY-MM-DD
last_updated: YYYY-MM-DD
```

There is NO `trigger` field and NO `frequency` field in the template frontmatter.
writer-subagent.md says the header requires "Persona, Trigger, Goal, Frequency".

**Missing sections mismatch**:

| writer-subagent.md requires | journey-template.md has |
|-----------------------------|------------------------|
| Journey Flow (Mermaid) | NOT present — template has no Mermaid flowchart section |
| Trigger field in header | NOT in frontmatter |
| Frequency field in header | NOT in frontmatter |
| Alternative Paths (section 4) | NOT present — only "Failure / Off-Path Handling" |
| E2E Test Scenarios | NOT present |
| Journey Metrics | NOT present |

Writers who follow the template produce 7-column touchpoint tables without Emotion data;
the writer's self-review check (line 3 in the self-review checklist "Touchpoint table present
with all 8 columns") would then FAIL on template-compliant journey files, causing spurious
PARTIAL ACKs.

## Suggested Fix

Reconcile the two sources of truth. Recommended approach:

**Update writer-subagent.md** (less disruptive than revising the template):
- Change the journey header requirement to match the template frontmatter (remove "Trigger" and
  "Frequency" from the header spec, or add them to the template frontmatter).
- Change the touchpoint table column requirement from "8 columns" to "7 columns" to match the
  template, or add "Emotion" and "Mapped Feature" columns to the template touchpoint table header.
- Remove "Alternative Paths", "E2E Test Scenarios", and "Journey Metrics" from the mandatory
  list if they are not in the template, or add them as H2 sections to the template.
- If Mermaid flowchart is required (writer guidance item 2), add a `## Journey Flow` section
  with a Mermaid block to the journey-template.md.

**Also update the self-review checklist evidence example** in writer-subagent.md:
- Change "Touchpoint table present with all 8 columns" to reflect the actual column count.
