## Symptom

`generate/planner-subagent.md` carries a truncated Snippet D IPC Contract block that omits
three subsections present verbatim in all seven other sub-agent prompts: the "Blocker-scope
taxonomy for writer self-review FAIL rows", the "`FAIL` ACK semantics (collapsed scope)"
section, and the "Self-review FAIL rows do NOT trigger `FAIL` ACK" paragraph. The FORBIDDEN
subsection is also abbreviated. This means the planner prompt is NOT self-contained per the
Snippet D contract — a reader of `planner-subagent.md` alone cannot derive the full IPC
behavior expected of the planner.

## Evidence

**All other sub-agents** contain this block in their IPC Contract section
(confirmed by `grep -l "Blocker-scope taxonomy"` across all 7 other agents):

```
### Blocker-scope taxonomy for writer self-review FAIL rows

| `blocker_scope` | Definition |
|-----------------|-----------|
| `global-conflict`       | ...
| `cross-artifact-dep`    | ...
| `needs-human-decision`  | ...
| `input-ambiguity`       | ...
```

**planner-subagent.md IPC Contract section** (lines 1–43): the section jumps directly from
the Role → final-path mapping table to FORBIDDEN, with NO blocker-scope taxonomy, NO FAIL ACK
semantics section, and NO paragraph about "Self-review FAIL rows do NOT trigger `FAIL` ACK."

**FORBIDDEN section comparison**:

planner-subagent.md (lines 38–42) has only 3 bullets:
```
- FORBIDDEN to write any HTML-comment IPC envelope into artifact leaves.
- FORBIDDEN to include content in the Task return — ACK is one line only.
- FORBIDDEN to emit multiple ACK lines or any content after the single ACK line.
```

All other sub-agents have 4 bullets, with the first bullet being the full verbatim text:
```
- FORBIDDEN to write `<!-- metrics-footer -->`, `<!-- self-review -->`, or any HTML-comment
  IPC envelope into artifact leaves — artifact nudity is a hard constraint (guide §3.9 hard
  constraint 1). All process metadata goes to `.review/` archive files, never into the artifact.
```

And a fourth bullet about "硬修" (force-fix in-place) that the planner FORBIDDEN section
omits entirely (domain-consultant-subagent.md line 71, writer-subagent.md line 80, etc.).

**Self-contained-file principle violation**: the Snippet D contract is the IPC interface that
every sub-agent must implement. A planner that reads only its own prompt file cannot verify
whether its behavior violates the FAIL-row protocol (e.g., if a planner in a future evolution
gains a self-review phase, it has no blocker-scope taxonomy to reference). The cross-reviewer
(this very skill-forge sub-agent) checks CR-S08 (`ipc-footer-present`) across all sub-agents,
but the fingerprint line is present — it is the CONTRACT BODY that is truncated, not the
fingerprint marker.

## Suggested Fix

Restore the three missing subsections to `generate/planner-subagent.md` by inserting verbatim
from any other sub-agent prompt the following content between the Role → final-path mapping
table and the FORBIDDEN subsection:

1. `### Blocker-scope taxonomy for writer self-review FAIL rows` — the full 4-row table with
   `global-conflict`, `cross-artifact-dep`, `needs-human-decision`, `input-ambiguity` entries
   (see `generate/writer-subagent.md` lines 39–51 for the canonical text).

2. `### \`FAIL\` ACK semantics (collapsed scope)` — the paragraph listing the three technical
   failure conditions (Write tool denied, prompt parse error, timeout with zero writes) plus the
   `Self-review FAIL rows do NOT trigger \`FAIL\` ACK` paragraph
   (see `generate/writer-subagent.md` lines 53–71 for canonical text).

3. Replace the abbreviated first FORBIDDEN bullet with the full verbatim text including the
   guide §3.9 reference.

4. Add the fourth FORBIDDEN bullet about "硬修" (force-fix in-place) of global-conflict FAIL rows.

Note: the planner does not produce self-reviews, so these sections are informational for the
planner's own compliance, but they must be present for the IPC contract to be self-contained
(the planner needs to know what the FAIL ACK means when it receives ACKs from sub-agents
it dispatches if it ever evolves to a dispatch role).
